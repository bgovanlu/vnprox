## What was built
A federation primary that attaches multiple PVE clusters as app-owned registry entries and aggregates reads with per-cluster failure isolation. Config ownership stays strictly per-cluster — no cross-cluster mutation primitive exists.
- `internal/federation/` — cluster registry `Service` (CRUD) + `Aggregator` fanning reads to N clusters' `internal/pve.Client`s concurrently, with `partial`/`failedClusters` isolation mirroring the existing peer fan-out envelope.
- `internal/store/clusters.go` (+ `_test.go`), `internal/store/migrations/0021_clusters.sql` — `clusters` table; credential material encrypted at rest via the AES-256-GCM session-ticket primitive (ciphertext asserted never to contain plaintext token). Schema version bumped to **21** in `kv_test.go`.
- Per-cluster changeset scoping: `Changeset.ClusterID` (additive; empty = implicit default/local cluster) + `internal/change/validate_crosscluster.go` — rejects any op whose target Ref belongs to a different attached cluster (`codeCrossClusterRef`), wired via the optional `ClusterMembership` seam in `service.go`/`raw_service.go`. No-op for single-cluster deployments.
- Global audit: `internal/store/audit.go` + `clusterId` dimension, `partial`/`failedClusters` on unreachable clusters.
- `internal/api/federation.go` (+ `_test.go`) — `GET/POST /federation/clusters`, `GET/PUT/DELETE /federation/clusters/{id}` (netWrite-gated mutations).
- `internal/pvemock/clustergroup.go` — run N independently-addressed mock clusters in one test process, one killable mid-aggregation.
- Docs: `docs/data-model.md` (clusters shape), plus api/security doc updates.
