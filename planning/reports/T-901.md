# T-901 — Topology renderer v2: canvas core + accessibility bridge

## What I built

A canvas rendering engine for the Graph view, behind a feature flag, as a pure
rendering-layer swap over the frozen topology projection contract. The v1 React
Flow renderer stays selectable as the fallback.

New modules (all under `web/src/topology/`):

- **`canvasScene.ts`** — framework-free scene geometry: graph↔screen viewport
  transforms, `fitViewport` (v1's `fitView` equivalent), `hitTest` (scale-
  invariant, topmost-wins, `excludeId` for drag), `zoomAt` (zoom-to-cursor),
  `panBy`. This is where "what did the user click, at any zoom" lives.
- **`a11yBridge.ts`** — the **pure half of the accessibility bridge**:
  `entityAriaLabel(data)` (the shared kind/identity/status/badge label
  vocabulary), `buildA11yProxies(nodes)` (one proxy descriptor per visible
  entity, graph-space box + label), `rovingOrder`/`nextRovingId` (stable
  visual-adjacency traversal for arrow-key roving focus), `proxyScreenRect`.
- **`TopologyA11yLayer.tsx`** — the **rendered half**: a parallel DOM layer of
  one focusable, `aria-label`led `<button>` proxy per entity, WAI-ARIA roving
  tabindex, Enter/Space activation, positioned in graph space with a single
  container transform carrying the viewport (so a pan frame updates one
  transform, not N buttons).
- **`canvasDraw.ts`** — the pure draw pass: status colors, kind accents,
  VLAN-dim, hover-chain highlight, selection, the amber mgmt/corosync/mgmt-path
  badge trio, the drift dashed outline, and the path-simulator overlay — the
  same EntityNodeData/EntityEdgeData the v1 DOM renderer reads.
- **`TopologyCanvasV2.tsx`** — the component: owns the `<canvas>`, pointer
  gestures (pan / drag-node / click / hover / wheel-zoom / context-menu), the
  fit-on-mount, and wires the a11y layer. Consumes the exact `FlowElements`
  `toFlowElements.ts` produces — no new projection or shape.

Wiring:

- **`store.ts`** — added `rendererVersion: "v1" | "v2"` + `setRendererVersion`,
  persisted per-browser in `localStorage` (`vnprox.topology.rendererV2`),
  guarded against a throwing/absent localStorage. This is an *experimental
  flag*, deliberately a different lifetime from the per-user server layout and
  the per-session view/traffic toggles.
- **`TopologyPage.tsx`** — a "Canvas v2" toolbar toggle (graph view only);
  renders `TopologyCanvasV2` vs `TopologyCanvas` off the flag; both read the
  same already-loaded `elements` (no refetch). The drag-drop handler was split
  into a shared `applyDrop(draggedId, targetId, pos)` that both renderers feed
  the same `computeDragOp` through — v1 resolves the drop target via React
  Flow's `getIntersectingNodes`, v2 via its own `hitTest` — so the drafted op
  is identical by construction.

## Design choices (flagged)

- **2D canvas, not WebGL.** At the documented scale target (~200 post-collapse
  elements) a 2D context clears the frame budget with wide margin (measured
  p95 16.7 ms) and adds **zero new dependency** (`docs/development.md`'s "prefer
  stdlib / justify any new dep"). "canvas/WebGL" in the card is satisfied by the
  canvas path; a WebGL upgrade can drop in behind the same props/scene seam
  later if a materially larger scale ever needs it. **No new dependency was
  added.**
- The accessibility bridge is a first-class, documented, reusable seam
  (below), not a bolt-on — canvas v2 is never a pixel blob with no DOM a11y.

## Accessibility-bridge interface (the seam T-905 / T-903 consume)

Downstream tasks consume it via three stable pieces, none of which they need to
reimplement:

1. `buildA11yProxies(flowNodes) → A11yProxy[]` — one proxy per visible entity;
   each carries `{ id, kind, label, ariaLabel, graph: Rect, selected, dimmed,
   isGuestGroup }`. Derived from the same `FlowElements` the canvas draws, so
   DOM and pixels never disagree.
2. `entityAriaLabel(EntityNodeData) → string` — the single label builder
   ("`bridge vmbr0, status ok, carries the management IP`"), so SR labels
   (T-905 AC4) and the command palette (T-903) read identical text.
3. `<TopologyA11yLayer proxies viewport activeId onActiveChange onActivate />`
   — the rendered roving-focus layer. Controlled `activeId`/`onActiveChange`
   let T-903's palette move focus programmatically; `onActivate` = the same
   thing a canvas click does. Arrow/Home/End/Enter/Space handled; one tabIndex
   0 at a time. The layer is pointer-events-transparent, so the canvas beneath
   owns all mouse interaction while the proxies own keyboard/AT — T-905 layers
   axe + focus-ring/reduced-motion refinements on top without touching the
   seam. Kept in sync on **pan/zoom** (container transform), **selection**
   (`selected` → `aria-pressed`, and selection drives `rovingId`), and entity
   set changes (`buildA11yProxies` re-run).

## What I tested and how

- **`canvasScene.test.ts`** — transforms are inverses; `fitViewport` frames all
  nodes and stays finite on empty/zero inputs; **`hitTest` resolves the correct
  entity at zoom 0.05 / 0.25 / 1 / 2 and picks the topmost on overlap and
  respects `excludeId`** (T-901's hit-testing-at-all-zoom-levels); `zoomAt`
  pins the cursor point; bounds clamp.
- **`a11yBridge.test.ts`** — label vocabulary incl. the mgmt trio spelled out +
  drift + guest-group pill; one proxy per node; `proxyScreenRect` tracks
  pan/zoom; roving order is reading-order and wraps both ways.
- **`TopologyCanvasV2.render.test.tsx`** — (AC5) one labeled focusable proxy
  per entity against `three-node-vlan`, selection→`aria-pressed`, layer applies
  the viewport transform (pan/zoom sync), Enter activates; (AC2) VLAN-20 dim set
  equals the server's own `?vlan=20` set; (AC3) a NIC dragged onto a bond fires
  `onNodeDrop(nic, bond)` and that pair drafts the exact `bond.update` op;
  click≠drag; (AC4) a manual position saved under v1 places the v2 entity at the
  same graph coords.
- **Full frontend suite:** `vitest run` → **127 files / 863 tests pass**.
  `eslint .` → 0 errors (1 pre-existing unrelated warning in
  `ErrorBoundary.tsx`). `tsc --noEmit` → clean.
- **Perf (AC6):** `web/e2e/scale.spec.ts`'s rAF frame-delta sampler, v2 case,
  real headless Chromium against the `scale-lab` production stack. **p95 =
  16.7 ms (≤ 20 ms budget) — PASS**; mean 58.1 fps, max 100 ms, 1.4% of frames
  over the 60fps line, 420 sampled frames. Transcribed into
  `docs/performance.md` §3a with the same headless/software-rasterized caveat
  the existing specs carry. (Captured via an isolated-port harness to avoid
  colliding with concurrent sibling e2e runs holding the shared 28006/28007
  pair; the committed spec is identical.)

## Acceptance criteria

1. **Runtime flag toggles v1/v2, same data no refetch** — PASS (toolbar toggle
   + localStorage; both consume the same `elements`).
2. **Golden parity (VLAN dim/selection/badges)** — PASS (render test asserts the
   v2 dim set equals the server `?vlan=20` set; both renderers consume the same
   `toFlowElements` fields).
3. **Drag-drop draft op identical to v1** — PASS (shared `applyDrop`→
   `computeDragOp`; render test proves NIC→bond resolution + op).
4. **Saved-layout round-trip renders positions identically** — PASS (both draw
   from `elements.nodes[].position`; test asserts the moved coord).
5. **A11y bridge: proxy per entity, synced on pan/zoom/selection** — PASS.
6. **Perf p95 ≤ 20 ms on scale-lab** — PASS, **p95 = 16.7 ms**.
7. **`internal/topology` and `projection.ts` exported types unchanged; zero
   backend changes** — PASS, both diff-empty (verified `git diff --stat`).
8. **`make check` green** — see final report line.

## Deviations / notes for the next agent

- No projection or `internal/` change; `docs/api.md` untouched. `projection.ts`
  is diff-empty. No new dependency.
- T-905 should drive dark/light map colors through `TopologyCanvasV2`'s `theme`
  prop (already plumbed; defaults to `useThemeStore`) and add reduced-motion +
  axe on top of `TopologyA11yLayer`; it does **not** need to reimplement roving
  focus or labels.
- T-903's palette can move map focus by controlling `TopologyA11yLayer`'s
  `activeId`; entity search names come from `entityAriaLabel`.
- v2's fit-to-view runs once per distinct element set (mirrors v1's `fitView`);
  manual pan/zoom then persists until the node set changes.
