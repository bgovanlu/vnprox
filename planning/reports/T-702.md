# T-702 · Management-path visibility: detect, badge, inspect — report

## What was built

**Shared classification/path resolver**
- `internal/topology/mgmtpath.go` (new): `MgmtRole` (`mgmt`/`corosync`), `MgmtRoleRef`, `MgmtPath`,
  `ResolveMgmtPaths(snap, refs)` (walks carrier → parent bridge for a VLAN sub-interface carrier →
  bridge ports → bond slaves → PhysNics, and a `redundant` bool over confirmed link-up terminal
  NICs), and `ApplyMgmtBadges(t, paths)` — a pure decorator over an already-`Project`ed
  `topology.Topology`, painting `mgmt`/`corosync` on each ref's own node and `mgmt-path` on every
  entity in its resolved `Path`. `Project` itself is untouched.
- `internal/change/protected.go`: `DetectProtected` is now a thin wrapper deriving its flat
  `ProtectedSet` from the new `DetectProtectedRoles` (role-tagged: an address can satisfy both
  `RoleMgmt` and `RoleCorosync` at once). New `classifyConfirmedRoles` does the same
  role-classification for an onboarding-confirmed `ProtectedSet`. Both share `wantedRoleAddrs`/
  `matchRoles`, the role-aware generalization of the old `addrMatchesAny` — same dual (raw-string,
  then parsed-CIDR-host) matching, so `DetectProtected`'s ref-inclusion set is byte-identical
  (AC5; see "Testing" below). New `MgmtStatus` type (`Source`, `Nodes map[string][]topology.MgmtPath`,
  `BadRefs`).
- `internal/change/service.go`: new `Service.MgmtStatus(ctx)` — loads protected.json, falls back to
  live `DetectProtectedRoles` when it has no node entries (`source: "detected"`), else classifies the
  confirmed set (`source: "confirmed"`), and calls `topology.ResolveMgmtPaths` — the **same**
  computation both new consumers below read from.

**API**
- `internal/api/protected.go`: `ProtectedService.MgmtStatus`, `GET /protected-interfaces/status`
  (`{source, nodes: {"<node>": [{ref, roles, path, redundant}]}, badRefs?}`).
- `internal/api/topology.go`: `MgmtStatusService` seam + `paintMgmtStatus` — decorates `GET
  /topology`'s response with the same badges, mirroring the existing `paintFindings`/`paintDrift`
  handler-level seam exactly (`Project` stays pure; `internal/api` supplies the extra input).
  `router.go`'s `Options.Protected` now doubles as this badge-painting input (nil-safe, same
  degraded-mode convention as `Drift`/`Findings`).

**Findings**
- `internal/findings/health_mgmtpath.go`: `CheckMgmtSinglePath = "mgmt_single_path"`, `MgmtProvider`
  seam, `checkMgmtSinglePath` — one `SeverityWarning` finding per (node, mgmt-role ref) whose
  resolved path isn't redundant. Deliberately hysteresis-exempt (no debouncer) per the card —
  structural, not counter-based. Corosync-only refs never fire (losing corosync-link redundancy
  isn't "the node becomes unreachable"). Wired into `Engine.healthFindings`; because the existing
  finding-badge overlay (`GET /topology`'s `"drift"` badge) already paints from *any* unified
  finding's `Refs`, the carrier gets dashed automatically — no extra wiring needed for AC3's last
  clause.
- `cmd/vnproxd/findings.go`/`server.go`: `mgmtStatusAdapter` (a lazily-set, mutex-guarded adapter,
  since `findings.Engine` is constructed before `change.Service` exists in `server.go`'s startup
  order — filled in with the real `*change.Service` immediately after `change.NewService` succeeds,
  always before the daemon serves requests or `RunLoop` runs).

**pvemock / fixtures**
- `testdata/clusters/single-node.yaml`: added spare `eno2` (unconfigured, link-up) — proves the
  resolver only walks the actual carrier's path, not every link-up NIC on the node; also the
  redundancy candidate T-703's wizard will pick from.
- `testdata/clusters/vlan-mgmt.yaml` (new): single node, mgmt IP on a VLAN sub-interface
  (`vmbr0.30`) over a plain trunk bridge (`vmbr0` → `eno1`) — the "mgmt-on-VLAN-sub-interface" case.
- **Deviation:** did *not* add corosync-ring serving to `internal/pvemock/hostreader.go`. Production
  corosync detection already reads `/etc/pve/corosync.conf` directly (a single local file read
  covers the whole cluster — pmxcfs-replicated, `internal/host/corosync.go`'s own doc comment); it
  was never part of the per-node `HostReader`/`collect` poll pipeline, and T-702's `MgmtStatus`
  reuses that exact mechanism unchanged. Golden tests hand-build `*host.CorosyncConfig` /
  `topology.MgmtRoleRef` inputs instead (mirroring the existing convention in
  `internal/change/protected_test.go` and `internal/api/protected_test.go`), which kept this task
  from having to restructure the collect pipeline. Noted as a deliberate scope call, not an
  oversight.

**Frontend**
- `web/src/api/types.ts` / `protectedInterfaces.ts`: `ProtectedInterfacesStatusResponse`,
  `ManagementPathRef`, `fetchMgmtStatus`.
- `web/src/topology/queries.ts`: `useMgmtStatusQuery`.
- `web/src/topology/EntityNode.tsx`: distinct amber treatment (chip color + tooltip) for
  `mgmt`/`corosync`/`mgmt-path` badges, additive to the plain-grey badge chip every other badge gets.
- `web/src/topology/switchModel.ts`: `SwitchPortNic.badges` (threaded from the underlying node so
  the faceplate can mark uplink-bay NIC chips on the path).
- `web/src/topology/SwitchFaceplate.tsx`: same amber treatment on the chassis header (carrier
  badges) and on uplink/NIC port chips carrying `mgmt-path`.
- `web/src/topology/InspectorPanel.tsx`: new "Management path" tab (node-scoped entities only) —
  every resolved ref for that node: carrier, path chain, a plain-English redundancy statement
  (`describeMgmtPathRedundancy`), and — when `source: "detected"` — a caveat plus a working
  "Review protected interfaces" button that re-opens the onboarding walkthrough at its `protected`
  step (reuses `useOnboardingProgressQuery`/`useSaveOnboardingProgressMutation` + `resumeOnboarding`;
  there's no dedicated deep-linkable onboarding route in this codebase, so this reopens the
  always-mounted `<OnboardingWalkthrough/>` at the right step rather than navigating to a URL).

**Docs**
- `docs/api.md`: `GET /protected-interfaces/status` route + response-shape paragraph; `GET
  /topology` management-path badge paragraph; `mgmt_single_path` added to the `GET /findings`
  check-name list and the hysteresis-exemption note.
- `docs/features/topology.md` §3: management-path visibility paragraph + badge vocabulary
  (`mgmt`/`corosync`/`mgmt-path`) + rendering-per-surface summary.
- `docs/features/monitoring.md` §5: `mgmt_single_path` check description (hysteresis-exempt,
  detection-only, T-703's entry point).
