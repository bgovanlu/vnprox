# T-1203 — Cross-cluster IPAM, external subnets & bidirectional sync

## What I built

External (non-PVE) subnets are now first-class IPAM records, a cross-cluster IPAM view surfaces
duplicate/overlapping subnets across attached clusters as conflict findings, and the NetBox/phpIPAM
bridge is upgraded from read-merge to bidirectional sync — with the sync writes staged/confirmed/
audited exactly like the change engine's contract even though they sit outside `internal/change` by
nature.

### Store
- **Migration `0023_external_subnets.sql`** (numbered per the Phase-12 reservation, after
  `0021_clusters.sql`/`0022_switches.sql`). `external_subnets` (id, cidr UNIQUE, label, source
  `manual|netbox|phpipam`, description, created_by, created_at, updated_at) — app-owned intent only.
- **`internal/store/externalsubnets.go`** — `ExternalSubnetRepo` (Insert/Get/List/Update/Delete),
  `ExternalSubnet` struct, provenance constants. Table-driven test (`externalsubnets_test.go`).
- **`internal/store/kv_test.go`** — schema-version assertion bumped `22` → `23`.

### internal/ipam
- **`external.go`** — `ExternalSubnet` app type, `ExternalSubnetStore` seam, service CRUD
  (`ListExternalSubnets`/`Get`/`Create`/`Update`/`Delete`) with CIDR validation+canonicalization,
  and `externalSubnetRows` so external records render as `source: "external"` (readOnly) rows in
  `GET /ipam/subnets` alongside sdn/bridge rows.
- **`crosscluster.go`** — `ClusterSubnets` input type and `CrossClusterConflicts` which folds N
  clusters' subnet CIDR sets into `cross_cluster_duplicate_subnet` conflicts (a new `Conflict.type`
  reusing the existing `Conflict` shape with an added `Clusters []string` cluster-pair field).
  Deterministic, de-duplicated output.
- **`sync.go`** — the bidirectional-sync diff engine: `ExternalIPAMClient` bridge seam,
  `ExternalSyncPreview` (pure dry-run), `ExternalSyncApply(confirm)` (writes only on confirm,
  returns per-record before/after for the audit trail), and `ExternalSyncFindings`
  (`external_ipam_drift`/`external_ipam_conflict`). `ErrSyncConfirmRequired`/`ErrSyncNotConfigured`.
- **`types.go`** — `Conflict.Clusters` field + conflict-type constants.
- **`service.go`** — `External`/`ExternalIPAM` added to `Config`/`Service`.

### internal/federation

## Deviations
- **`ExternalIPAM` (concrete write client) left nil in production wiring.** The sync engine, diff,
  preview/apply/confirm/audit ceremony, and findings are complete and fully tested against an HTTP
  double, but a production client keyed to real NetBox/phpIPAM REST shapes needs hardware
  validation (logged in `needs-hardware-validation.md`). Until configured, the sync routes return
  `404 not_found` ("not configured"). This keeps the safety-critical write ceremony fully built and
  tested without guessing external API shapes.
- **External-subnet CRUD availability follows the ipam service's PVE-available gate.** `ipamConcrete`
  is only constructed when a PVE client exists; external-subnet routes ride the same object.
  Acceptable given the composition root's existing degraded-mode convention; a future refactor could
  make external subnets available even with no PVE client.
- **`GET /federation/ipam/conflicts` compares SDN subnet CIDRs per cluster** (via the aggregator's
  PVE fan-out), not each cluster's full `GET /ipam/subnets` (bridge/external rows), because remote
  attached clusters are PVE clusters reached through their PVE API, not vnprox instances. This is
  the faithful reading of "backed by the aggregator across attached clusters' subnets".
