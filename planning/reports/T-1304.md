## What was built

**`internal/guestinterior` (new package)** — the read/parse engine, source-agnostic:

- `View` (`types.go`): `{interfaces, addresses, routes, dns, listeningSockets,
  defaultGatewayReachable, source}` — the shape `GET /guests/{ref}/interior` serializes almost
  verbatim.
- `parse.go`: `FromAgentInterfaces` (QEMU guest-agent's `pve.AgentIface` → `Interface`/`Address`),
  `ParseIPAddrJSON`/`ParseIPRouteJSON` (`ip -j addr|route show` JSON), `ParseResolvConf`
  (`/etc/resolv.conf`), `ParseSS` (`ss -H -tuln` plain text) — all defensive on malformed/truncated
  input (parse to an empty/partial result, never panic or error the whole read).
- `qemu.go`: `FetchQEMU` — addresses/interfaces via `GetGuestAgentInterfaces` (T-405); routes/DNS/
  sockets via three new `agent/exec` command shapes, reusing T-802's `AgentExec`/`AgentExecStatus`
  poll loop (a small local `fetchExec` helper, since `internal/probe.Run` classifies a *probe*
  result, not arbitrary stdout); default-gateway reachability reuses `internal/probe.Run` itself
  (an icmp probe toward the parsed default route's gateway) — no new probe logic.
- `lxc.go`: `FetchLXC` — the container counterpart, over `internal/host.Reader.ContainerInterior`/
  `ContainerPing` (below), sharing every parser `FetchQEMU` uses except the address source (`ip -j
  addr show` instead of the guest-agent's own shape, since a container has no guest agent).

**`internal/host`** — the LXC host-side read primitives (T-1304's own addition to `Reader`):

- `ContainerInterior(ctx, node, vmid) (ContainerInteriorRaw, error)`: `{addrJson, routeJson,
  resolvConf, sockets}`, raw bytes, parsed by `internal/guestinterior`.
- `ContainerPing(ctx, node, vmid, targetIP) (bool, error)`: a single best-effort ping.
- `containerinterior_linux.go` (Real, linux-only): resolves the container's init pid via
  `/sys/fs/cgroup/lxc/<vmid>/cgroup.procs` (flagged needs-hardware-validation below), then execs
  `ip -j addr|route show` / `ss -H -tuln` / `ping` inside the container's netns via `nsenter
  --net=/proc/<pid>/ns/net`; `resolv.conf` is read directly off `/proc/<pid>/root/etc/resolv.conf`
  (a plain file, no netns entry needed). New overridable `Real` fields (`NsenterPath`/`IPPath`/
  `SSPath`/`PingPath`) mirror the existing `LLDPCommand`/`BGPSummaryCommand` pattern.
  `netlink_other.go` (non-linux stub) and a skip-if-absent integration test
  (`containerinterior_linux_test.go`, mirrors `TestReal_FRRBGPSummary_Installed`'s convention)
  round it out.
- `fixture.go`: `FixtureReader` delegates both methods to `pvemock.FixtureHostReader`.

**`internal/pvemock`** — fixture support for both source types:

- QEMU: `parseInteriorCommand` (`guest.go`) recognizes the three additional `agent/exec` argv
  shapes `qemu.go` emits (closed/enumerable, matching `parseProbeCommand`'s own convention — no
  generic argv-matching table); `handleGuestAgentExec` dispatches to it before falling through to
  the existing probe-command path. Backed by three new `GuestSpec` fields
  (`interior_routes_json`/`interior_resolv_conf`/`interior_sockets`); gateway reachability reuses
  the existing `agent_exec_outcomes` icmp scripting.
- LXC: `guestinterior.go` (new file) implements `ContainerInterior`/`ContainerPing` on
  `FixtureHostReader` directly (no HTTP round trip — this is a local host-side read, not a PVE API
  call), backed by four more `GuestSpec` fields (`interior_addr_json` + the three shared with the
  qemu case) plus `interior_ping_outcomes` (IP → reachable, exact-match, same "unscripted = no
  reply" convention `AgentExecOutcomes` uses for "no match = error").

**Cluster awareness (CLAUDE.md's "everything is cluster-aware" invariant)**: the QEMU path needs no
new plumbing — PVE's own REST API (which `AgentExec`/`GetGuestAgentInterfaces` call) is already
cluster-transparent. The LXC path is not: `internal/host.Reader.ContainerInterior`/`ContainerPing`
only ever serve their own node, so a peer-routed counterpart was added — `internal/peer`:
`GET /api/peer/host/container-interior?node=&vmid=` and `GET /api/peer/host/container-ping?node=&
vmid=&ip=` (`server.go`, `client.go`, `types.go`), additive at protocol version 2, following the
`links`/`fdb`/`neighbors` precedent exactly. `internal/api/guestinterior.go`'s `fetchLXCInterior`
resolves local-vs-peer by comparing the guest's node against `LocalNode()` and, when remote, looks
the node up in `PeerContainerSource.Peers()` — exercised end to end by
`TestGetGuestInterior_LXC_PeerNode` (a fake `PeerContainerSource`, not a live HMAC round trip; see
Testing below for why).

**`internal/store`** — `guest_interior_toggles` (migration `0011_guest_interior_toggles.sql`, next
free version number in this worktree): `{ref, enabled, updated_by, updated_at}`, one row per guest
ever toggled, off-by-default for a guest with no row — `internal/store/guestinteriortoggle.go`'s
`GuestInteriorToggleRepo`.

**`internal/api`** (`guestinterior.go`, `router.go`) — the routes:

- `GET/PUT /guests/{ref}/interior-toggle` — `{ref, enabled}`.
- `GET /guests/{ref}/interior` — `{interfaces, addresses, routes, dns, listeningSockets,
  defaultGatewayReachable, source, ipamDiff}`; `404 interior_not_enabled` when the toggle is off
  (AC3); `503 interior_unavailable` when the read couldn't be attempted (no PVE session, no
  reachable host/peer route); audited `guest.interior_read` (reuses `ProbeAudit`'s seam — see
  `auditGuestInteriorRead`). Only mounted when `AuthService` implements `UsernameLookup` (needed for
  both the audit-row username and, matching `POST /simulate/verify`'s own precedent, there being
  someone to attribute the read to) — the toggle-GET route is mounted regardless.
- `ipamDiff`: `computeIPAMDiff` cross-checks every claimed address against
  `GuestInteriorIPAMSource.AllAllocations` (the existing, already-exported `*ipam.Service` method,
  reused — no new IPAM code) — `{ip, claimed: true, allocated, matches: claimed && allocated}` per
  address. That interface has exactly one method, a read; there is structurally no write path
  through this seam (the "zero IPAM writes" regression AC4 asks for).
- Wired in `cmd/vnproxd/server.go`: `GuestInteriorToggles` (new repo), `GuestInteriorGraph` (the
  same live graph `Simulator`/`Firewall` already use), `GuestInteriorHost` (`realHost`),
  `GuestInteriorPeers`/`GuestInteriorIPAM` (nil-safe typed-interface pattern, same as `peerAudit`/
  `ipamSvc` elsewhere in that file).

**Frontend** (`web/src`): `api/guestInterior.ts` + `api/types.ts` additions; `topology/
guestInteriorQueries.ts` (TanStack Query hooks — toggle query/mutation, interior query gated on the
toggle being on, a 404 `interior_not_enabled` response treated as "no data" not an error);
`topology/InteriorTab.tsx` (opt-in checkbox with plain-English "why it's off" copy; renders

## Deviations from the task card

- **`defaultGatewayReachable`'s honesty contract is narrower for the lxc path than the qemu path.**
  The qemu path reuses `internal/probe.Run`'s full `Outcome` (reachable/unreachable/timeout/error).
  The lxc path's `host.Reader.ContainerPing` collapses everything short of a successful ping into a
  single `false` — "no reply" and "could not even attempt it" are not distinguished. This was a
  deliberate scope simplification to avoid introducing a second honesty-contract-shaped `Outcome`
  type for one field; flagged in docs/api.md's Guest interior section and in
  `needs-hardware-validation.md` as a named follow-up rather than silently under-specified.
- **`ipamDiff`'s exact field semantics were inferred, not fully pinned by the card.** The card's
  prose (`ipamDiff: {claimed, allocated, matches: bool}`) only type-annotates `matches`. I chose
  `claimed`/`allocated` as booleans (`claimed` always `true` — this list only ever holds claimed
  addresses; `allocated` is whether IPAM has a record) with `matches = claimed && allocated`,
  satisfying AC4's literal wording exactly. Documented explicitly in docs/api.md so the next agent
  isn't guessing from the card text again.
- **No audit for the toggle routes**, only for `GET /guests/{ref}/interior` itself — matches
  `annotations`/`layouts`' "UI preference, not audited" precedent for the toggle, and
  `probe.verify`'s "reaches into a guest, audited" precedent for the read.
- **e2e (AC6) not confirmed green in this session** — see Testing above; environmental, not a
  defect in the spec or the feature, but flagged per CLAUDE.md rather than claimed as passing.
