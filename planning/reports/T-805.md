# T-805 — ARP/neighbor tables as IPAM enrichment

## What I built

Implemented the `internal/ipam.NeighborSource` seam the codebase reserved a slot
for (docs/features/ipam.md §1's flagged "known gap"), closing the loop so the IPAM
address list's third enrichment source — ARP/IPv6-neighbor tables, fanned in
cluster-wide — is live alongside guest-agent and DHCP-lease enrichment.

### Host-level read (`internal/host`)

- **New file `internal/host/neighbors.go`** (no build tag): the `host.Neighbor`
  type (`{IP, MAC, Iface, State}`), the `NeighborReachable/…/NeighborIncomplete`
  state vocabulary, `isResolvedNeighborState` (the REACHABLE/STALE/PERMANENT
  filter), `ParseProcNetARP` (a portable, unit-testable `/proc/net/arp` text
  parser that excludes not-yet-resolved entries via the ATF_COMPLETE flag bit),
  `readProcNetARP` (overridable-path file read), and `FixtureReader.Neighbors`
  (delegates to pvemock, applies the resolved-states filter).
- **New file `internal/host/neighbors_linux.go`** (`//go:build linux`):
  `Real.Neighbors` merges the IPv4 ARP table (`readProcNetARP`) with the IPv6
  neighbor table via `netlink.NeighList(0, FAMILY_V6)` (there is no `/proc` text
  equivalent for IPv6 neighbors), resolving link index → iface name and the NUD_*
  bitmask → the normalized state vocabulary; an IPv6-dump failure degrades to
  IPv4-only rather than erroring.
- **New file `internal/host/neighbors_other.go`** (`//go:build !linux`):
  `Real.Neighbors` stub returning `ErrUnsupportedPlatform`, matching
  `netlink_other.go`'s split.
- **New file `internal/host/neighbors_test.go`**: golden `/proc/net/arp` parser
  tests + the fixture-reader filtering test.
- **Modified `internal/host/reader.go`**: added `Neighbors(ctx, node)` to the
  `Reader` interface with a doc comment.

### Peer route (`internal/peer`) — additive, protocol-version-2, no bump

Following the `links`/`fdb` precedent exactly: added `GET /api/peer/host/neighbors`
to `HostReader`, `MountRoutes`, `handleNeighbors`, the `neighborsResponse` wire
type, and `Client.Neighbors`. HMAC-gated like every other peer route (it mounts
under the same `authMiddleware` subtree). Test: `TestTwoDaemonHarness_Neighbors`.

### Cluster fan-out (`internal/neighbor`) — new package

`internal/neighbor.Service` mirrors `internal/dhcp.Service`'s local-vs-peer
fan-out shape: reads the local node via `host.Reader`, every peer via
`GET /api/peer/host/neighbors`, tolerating one node's failure without blanking the
others (the "quietly absent" contract). Produces `ipam.Observation{Source:
"neighbor"}`. Implements `ipam.NeighborSource`. Wired into
`ipam.Config.Neighbors` in `cmd/vnproxd/server.go` (the same always-construct,
nil-Peers-tolerant pattern `dhcpSvc` uses).

## Deviations & notes for the next agent

- **`/proc/net/arp` cannot distinguish REACHABLE from STALE** (its Flags column
  only carries ATF_COMPLETE/ATF_PERM), so `ParseProcNetARP` normalizes every
  resolved non-permanent IPv4 entry to `REACHABLE`. The IPv6 path (netlink) gets
  the full REACHABLE/STALE distinction. This is an inherent format limitation,
  documented in `ParseProcNetARP`'s doc comment — flagged, not a bug. **Needs
  hardware validation:** the exact `/proc/net/arp` and netlink IPv6-neighbor
  output on a real PVE node was not verified against live hardware (developed
  against fixtures per CLAUDE.md). No new needs-hardware-validation.md entry was
  required by the task card's acceptance criteria, but a validator should confirm
  the ARP-flag and NUD-state mappings against a real node.
- **New package `internal/neighbor`** (mirrors `internal/dhcp`) — no new
  third-party dependency; `netlink` was already an approved dep used by
  `internal/host`.
- The `internal/collect.nodeHostReader` fan-out interface (T-303's host poller)
  was intentionally NOT extended: neighbor reads flow through the separate
  `internal/neighbor.Service` fan-out, not the inventory host poll, exactly like
  DHCP leases flow through `internal/dhcp.Service` rather than the poller.
