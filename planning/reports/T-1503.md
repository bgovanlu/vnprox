# T-1503 — Ceph network awareness

## What I built

A new `internal/ceph` package: **read-only forever** discovery of PVE's own Ceph public/cluster
network declaration and per-node OSD placement, physical bond/NIC attribution reusing
`internal/topology`'s existing NIC-path resolver, a pure map-layer projection, and the three
named footgun findings — plus the PVE client methods, mock-server routes, findings-engine wiring,
`GET /ceph/status` route, `cmd/vnproxd` composition-root wiring (classifier registration +
findings provider), and a first frontend layer-toggle contribution that make it reachable end to
end.

### `internal/ceph` (the engine)

- **`discover.go`** — `Discover(ctx, *pve.Client, nodes []string) (Status, error)`: one
  `GET /cluster/ceph/config` call plus one `GET /nodes/{node}/ceph/osd` call per named node,
  aggregated into `Status{PublicNetwork, ClusterNetwork, OSDs}`. A cluster with no Ceph installed
  degrades to a zero `Status` — never an error, matching `pve.CephConfig`'s own contract.
- **`project.go`** — `Project(snap inventory.Snapshot, status Status) Overlay`: for every node
  hosting ≥1 OSD, resolves which Bridge/VlanIface carries an address inside the declared public/
  cluster CIDR (`carrierInCIDR`, the two inventory kinds that declare an `Addresses` field), then
  walks that carrier's physical path via **`internal/topology.ResolvePhysicalPath`** — exported
  from this task (renamed from the previously-unexported `walkMgmtPath`, T-702's management-path
  resolver) specifically so this card could reuse it rather than re-implement a second
  carrier→bond→PhysNic walker. `ridingRef` picks the single bond ref if the path is bonded, or the
  sole bare terminal NIC if not — the "which bond does this OSD ride" answer, denormalized onto
  every `OSDAttribution` so an inspector never needs a second node lookup.
- **`findings.go`** — the three named footguns, each a pure function over `Overlay` (plus `snap`/
  `*host.CorosyncConfig` for the corosync check):
  - `CorosyncSharedLink`: a node's corosync ring address (from `host.CorosyncConfig`, the exact
    static substrate `cmd/vnproxd/serviceclassify.go` already reads for T-1504) resolves to a
    carrier sharing ≥1 terminal NIC with that node's Ceph cluster-network carrier.
  - `ClusterMTUMismatch`: OSD-hosting nodes' resolved cluster-network carrier MTU disagrees —
    majority-vote via **`internal/xnode.MajorityInt`**, newly exported from this task (renamed
    from `majorityInt`) so this check reuses `CrossNodeMTU`'s exact tie-breaking rule instead of
    re-implementing it (it cannot call `CrossNodeMTU` itself: that function groups by same-named
    bridge cluster-wide, and Ceph's per-node cluster-network carrier is frequently a
    *different*-named interface across nodes).
  - `SingleNIC`: a node's public and cluster networks both resolve to the exact same single,
    unbonded terminal NIC.
- **`types.go`** — `OSD` now carries a first-class `Ref` (`Kind` `ceph-osd`, `"osd<id>"` scoped to
  its node — new `inventory.KindCephOSD`, added to the closed `Kind` set following
  `KindVF`'s exact precedent: has a `Ref`, never itself graph/provenance-tracked).

### PVE client + mock server

- **`internal/pve/ceph.go`** — `Client.CephConfig`/`Client.CephOSDs`, two `GET`-only methods
  against `/cluster/ceph/config` / `/nodes/{node}/ceph/osd` — no new Ceph API client, no new
  credentials, the same boundary T-1206's PBS pattern establishes (per the task card).
- **`internal/pvemock/ceph.go`** + `types.go`/`server.go` extensions — `Fixture.Ceph`
  (`ClusterCephSpec`) and `NodeSpec.CephOSDs` fixture fields, two `PrivSysAudit`-gated handlers.
  Ceph placement is immutable fixture data (no handler mutates it), so it's served straight off
  `srv.state.fixture` rather than threaded through the mutable `nodeState`.

### Findings engine + API + composition root

- **`internal/findings/health_ceph.go`** — `CephProvider` seam (`CephOverlay() (ceph.Overlay,
  *host.CorosyncConfig, error)`), wired into `Engine.Config.Ceph`/`healthFindings()`. Re-derives
  each check's candidate key set from `Overlay` every cycle (not just currently-breaching keys) so
  the shared `cephDB` debouncer's `Evaluate(key, breach, ...)` calls see explicit `false`
  observations and a cleared footgun's hysteresis actually decays — a footgun-list-only producer
  fed straight into hysteresis would never clear.
- **`internal/api/ceph.go`** — `GET /ceph/status` (`netRead`-gated), serializing `ceph.Overlay`
  with every `inventory.Ref` field as its `.String()` form, the same round-trippable-through-
  `GET /inventory/{ref}` convention every other Ref-carrying response in this API uses.
- **`cmd/vnproxd/cephwire.go`** — `setupCeph`: reads `Status` once at startup (a Ceph network
  declaration changes on the order of a cluster's lifetime, mirroring `setupFlowClassifier`'s own
  documented rationale for corosync's ring addresses), registers `PublicNetwork`/`ClusterNetwork`
  with T-1504's `flow.Classifier` via the generic `flow.NewCIDRSource` constructor (**T-1503
  implements no classification logic of its own** — it supplies network declarations, exactly as
  `classify.go`'s own doc comment specifies this integration point), and returns a
  `*cephProviderAdapter` that re-projects that one-time-read `Status` against the graph's
  *current* snapshot on every findings cycle / `GET /ceph/status` call.

### Frontend (T-1503's scoped contribution — see Deviations)

- **`web/src/api/types.ts`** / **`web/src/api/ceph.ts`** — `CephOverlay`/`CephNodeAttribution`/
  `CephOSD` types and `fetchCephStatus()`.
- **`web/src/topology/cephOverlay.ts`** — pure overlay computation (`computeCephBadges`,
  `osdsForNode`, `attributionForNode`), mirroring `mtuOverlay.ts`'s "pure mapping function, unit-
  testable without a real canvas" precedent. Paints `ceph-public`/`ceph-cluster` badges onto
  existing bond/PhysNic map nodes (no synthetic OSD map node — an OSD is inspector-surfaced detail
  on an existing entity, not a first-class map entity, per `docs/data-model.md` §11).
- **`web/src/topology/LayerToggleBar.tsx`** — a 9th "Ceph" toggle, the exact optional-pair-prop
  convention (`cephLayerActive`/`onToggleCeph`) Flows/Latency/MTU/WireGuard already established.

## What I tested and how

- **`internal/ceph`**: golden projection tests (`project_test.go`) against `testdata/ceph/
  clean.yaml` (dedicated bonded public/cluster networks — asserts exact carrier/path/riding-on
  refs and per-OSD denormalized attribution) and `single-nic.yaml` (bare-NIC resolution alongside
  a cleanly-bonded second node in the same overlay) — both built via the standard
  pvemock→`internal/collect`→real `inventory.Snapshot` pipeline (`testhelpers_test.go`, mirroring
  `internal/topology`'s own convention), not hand-constructed graphs.
- **Findings** (`findings_test.go`): each of the three checks fires against its own dedicated
  fixture (`corosync-shared-link.yaml`, `mtu-mismatch.yaml`, `single-nic.yaml`) and all three stay
  silent against `clean.yaml` — table tests, one row per finding, per AC3. A nil
  `*host.CorosyncConfig` degrades `CorosyncSharedLink` to silence, never a panic or false positive.
- **Classifier integration** (`classify_test.go`, AC2): `Status.PublicNetwork`/`ClusterNetwork`
  registered into a real `flow.Classifier` via `flow.NewCIDRSource` classify synthetic flows
  `ceph-public`/`ceph-cluster` correctly; an out-of-range flow classifies `unclassified`.
- **Zero write surface** (`zerowrite_test.go`, AC4): source-scans this package and
  `internal/pve/ceph.go` for mutating-verb tokens; a request-recording wrapper around pvemock
  confirms `CephConfig`/`CephOSDs` issue only `GET`s (excluding the unrelated auth-ticket POST);
  a direct read of `internal/change/op.go` confirms no `"ceph."`-prefixed `OpType` exists.
- **`internal/pve`** (`ceph_test.go`): `CephConfig`/`CephOSDs` round-trip through a real
  `httptest.Server` wrapping pvemock — public/cluster CIDRs, per-node OSD placement (device/up/in),

- **`internal/pvemock`** (`ceph_test.go`): both routes return correct data and are `PrivSysAudit`-
  gated (401 unauthenticated).
- **`internal/findings`** (`health_ceph_test.go`): a fake `CephProvider` proves `ceph_single_nic`
  fires only after the 2-cycle rise threshold and clears after the fall threshold once the

- **`internal/api`** (`ceph_test.go`): `GET /ceph/status` serializes a fake overlay correctly,

- **`internal/topology`**/**`internal/xnode`**: existing suites re-run green after exporting

## Deviations from the task card

- **Frontend scope, flagged deliberately.** The card's "Map layer: Ceph public/cluster network
  overlay + OSD↔bond highlighting" deliverable is implemented as far as the data plumbing goes
  (types, `GET /ceph/status` client, pure badge-computation logic, the `LayerToggleBar` toggle
  button) and is unit-tested, but I did **not** wire the toggle into `TopologyPage.tsx`'s
  store/query/canvas-paint loop (the store-action + `canvasDraw.ts` badge-rendering + Playwright
  e2e work `mtuOverlay`/`wgTunnelEdges` each got). None of T-1503's five acceptance criteria
  require that wiring — they're all backend (projection, classifier, findings, zero-write-surface,
  docs) — so I judged it lower-risk to leave this named, rather than rush a large,
  intricate-to-verify canvas-painting change into `TopologyPage.tsx` without being able to visually
  confirm it. Flagged here explicitly rather than silently cut; the next agent touching the
  topology map should wire `cephLayerActive`/`onToggleCeph` + a `useQuery(fetchCephStatus)` +
  `computeCephBadges` into `TopologyPage.tsx`'s existing badge-painting path (`ApplyMgmtBadges`'s
  sibling) and add a `web/e2e/ceph-overlay.spec.ts`, following T-1402's WireGuard-layer PR as the
  closest precedent.
- **`internal/ceph.OSD` gained a `Ref`/`inventory.KindCephOSD`, not explicitly named in the task
  card's deliverables list.** The card's context docs cite "`docs/data-model.md` §1 (entity-kind
  extension pattern)" — read as an instruction to follow the pattern T-1506's `VirtualFunction`
  established (a `Ref`/`Kind` that is never itself graph/provenance-tracked) rather than leave OSDs
  as plain, unaddressable structs. Low-risk, additive-only change to `internal/inventory/ref.go`'s
  closed `Kind` set; every existing test in that package still passes.
- **No live Ceph rebalance/utilization data behind `ceph_corosync_shared_link`.** The finding
  detects *physical link sharing* only (no new dependency on `internal/metrics`/`internal/latmesh`
  was added) — its detail text states the qualitative risk without a measured "how saturated"
  figure. Flagged in `planning/reports/needs-hardware-validation.md`.
- Real PVE's exact `GET /cluster/ceph/config`/`GET /nodes/{node}/ceph/osd` wire shapes are this
  task's best-effort modeling (per `docs/development.md`'s "no live Proxmox cluster" constraint) —
  flagged as a dedicated needs-hardware-validation entry, along with Ceph's real
  `cluster_network`-defaults-to-`public_network` behavior and the two findings' real-world
  impact/severity.

## For the next agent

- `internal/ceph.Overlay`/`Status`/`Footgun` are the stable shapes T-1507 (migration planner) and
  any future Ceph-adjacent card should build on rather than re-deriving.
- `internal/topology.ResolvePhysicalPath` and `internal/xnode.MajorityInt` are now exported,
  general-purpose utilities — reuse them rather than re-implementing a carrier→bond walk or a
  majority-vote comparison a third time.
- Ceph's OSD `Ref` (`Kind` `"ceph-osd"`) is addressable but not inventory-graph-tracked — treat it
  like `VirtualFunction`'s `Ref`, not like a `Bridge`/`Bond` ref (no `GET /inventory/{ref}` entry
  will resolve it; it exists for identity/de-duplication in API responses and findings only).
- Frontend canvas-paint wiring for the Ceph layer is the one traced, explicitly-flagged gap above.
