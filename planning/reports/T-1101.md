## Frozen signatures (T-1102 / T-1105 / T-1106 / T-1107 build on these)

```go
const spec.Version = 1
func spec.Export(snap inventory.Snapshot) spec.Spec
func spec.Import(s spec.Spec, live inventory.Snapshot) (ops []change.Op, notInSpec []inventory.Ref, err error)
func spec.Marshal(s spec.Spec) ([]byte, error)
func spec.Parse(data []byte) (spec.Spec, error)
```

`Export` takes an `inventory.Snapshot` alone (not separate sdn/firewall/ipam views): SDN zones/vnets/subnets are already inventory entities. `Import` returns `(ops, notInSpec, err)` — a 3-tuple, not a wrapper struct.

## Spec schema (specVersion 1; every non-identity field is omitempty)

```yaml
specVersion: 1
nodes:                        # sorted by name
  - name: pve1
    bonds:                    # Linux bonds; sorted by name
      - {name, mode, slaves[], lacpRate, xmitHashPolicy, mtu}
    bridges:                  # Linux bridges; sorted by name
      - {name, ports[], vlanAware, vids[], addresses[], gateway, mtu, stp, comments}
    vlans:                    # plain 802.1q sub-interfaces; sorted by name
      - {name, parent, vid, addresses[], mtu}
sdn:                          # omitted when the cluster has no SDN objects
  zones:   [ {id, type, bridge, controller, ipam, nodes[], exitNodes[], peers[], vrfVxlan, mtu} ]  # sorted by id
  vnets:   [ {id, zone, alias, tag, vlanAware} ]                                                    # sorted by id
  subnets: [ {id, vnet, gateway, dnsZonePrefix, dhcpRanges[], snat} ]                               # sorted by id
```

`vids` are inventory `VidRange` string forms (`"100"`, `"2-4094"`), sorted.

### AC2 (byte-identical round-trip) and AC5 (no implicit prune) — the two load-bearing properties

- **Byte-stable (AC2/AC4):** `Spec` has no timestamp and is a pure typed-struct tree (no `map[string]any`). `Export` sorts every collection by a stable key before it ever reaches `Marshal`, and `yaml.Marshal` walks struct fields in declaration order — so nothing in the pipeline touches a Go map's randomized iteration. The round-trip is exact because `Export` reads the *same* declared fields (`DeclaredPortNames`, `DeclaredSlaves`, `*.MTUDeclared`, …) that `Import`'s diff compares against.
- **No implicit prune (AC5):** `Import` emits create/update/port-add/port-remove ops only — there is no delete path anywhere in the package. Entities live-but-absent-from-spec are returned in the distinct `notInSpec` list; the caller decides. `POST /spec/import` surfaces them as `Ref` strings alongside the draft changeset and never turns them into ops.

## Scope decisions (flagged)

- **Reconcile scope = the six kinds the blueprint diff engine already covers**: `bond`, `bridge`, `vlan`, `sdn-zone`, `sdn-vnet`, `sdn-subnet`. **Firewall rulesets and IPAM allocations are deliberately excluded from the v1 spec.** The card's objective prose lists "firewall, IPAM ranges", but the diff pattern I was told to mirror (`blueprint.Instantiate`/`adapters.go`) covers exactly those six kinds; firewall rule-ordering/`fw.rule.move` reconcile is a separate, larger effort with no AC or mirror-pattern here, and folding it in blindly at a semantics-freezing checkpoint would be the wrong call. Documented in `docs/data-model.md` §6; a later `specVersion` can add them additively (YAML is forward-additive). IPAM DHCP ranges *are* covered via `SubnetSpec.dhcpRanges`.
- **OVS out of scope:** OVS bridges/bonds and OVS Int Ports (`VlanIface.virt == "ovs"`) are neither exported, reconciled, nor reported in `notInSpec` — same reason (the v1 op vocabulary the blueprint diff targets is the Linux path).
- **omitempty = "not managed", including booleans.** Consistent with `blueprint.capture`/`adapters`: a `false`/omitted `vlanAware`/`stp`/`snat` means "don't manage this flag", so only a spec value of `true` diverging from live produces an op. **Reconciling a flag back to `false` is not expressible in v1** — the conservative choice keeps a partial hand-edit from silently emitting a disable op. Documented in §6.
- **Doc section number:** the card asked for "new §5"; §5 was already taken by T-806's live-probe table, so the schema is **§6**. Noted inline in the doc.
