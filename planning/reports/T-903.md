## What was built

**`web/src/keyboard/actions.ts`** — the `usePaletteActions` registry: a zustand store keyed by an
arbitrary `ownerId`, so any number of mounted pages/panels can each register their own
`PaletteAction[]` on mount and have them removed again on unmount, without colliding with any other
owner's ids. `useAllPaletteActions()` exposes the flattened, currently-registered list. The flattened
list is itself stored in state (`allActions`, recomputed only inside `setOwnerActions`/
`clearOwnerActions`) rather than derived inline in the selector — an inline `Array.from(...).flat()`
selector returns a new array on every read regardless of whether anything changed, which breaks
zustand v5's `useSyncExternalStore`-based subscriptions with an infinite re-render loop (hit this in
testing, see below).

**`web/src/keyboard/CommandPalette.tsx`** — the ⌘K/Ctrl+K dialog. Merges `SpotlightSearch`'s fuzzy
entity search (`GET /inventory/search` via the existing `useSearchQuery`) with every registered
palette action into one list, arrow-key/mouse highlight, Enter/click to run. Selecting an entity sets
the shared topology-store selection and navigates to `/topology` (mirrors `TopBar.tsx`'s existing
global search button, since the dialog is mounted app-wide, not scoped to the Topology page).
Running an action calls its `perform()` and closes the dialog.

**`web/src/keyboard/shortcuts.ts` / `useKeyboardShortcuts.ts`** — added a `"command-palette"`
`ShortcutAction` variant and a `SHORTCUTS` entry (`⌘K / Ctrl+K`) purely for `ShortcutHelpDialog` to
read from (same "one list, never drifts" pattern as every other binding). Dispatch is special-cased,
like `"?"`/help already was: `useKeyboardShortcuts` now takes `{ onOpenHelp, onOpenPalette }` and
checks `(metaKey || ctrlKey) && key==="k"` **before** the existing "ignore any modified keystroke"
guard (every other binding in this file is a plain unmodified key/chord, so that guard was safe to
leave first before this card). Deliberately fires even when focus is inside a text field — matches
the conventional cross-app meaning of the combo.

**`web/src/keyboard/ShortcutHelpDialog.tsx`** — unchanged rendering for the static `SHORTCUTS` list
(now includes the ⌘K row), plus a second "Available now, via the command palette" section listing
every currently-registered `PaletteAction` with `⌘K` as its invocation key — satisfies "the palette
binding plus at least the four named verbs' shortcuts where bound" by construction (reads the live
registry rather than a hand-maintained list that could drift from what's actually registered).

**`web/src/keyboard/rovingFocus.ts`** — framework-free pure functions: `visualAdjacencyOrder`
(sorts `{id,x,y}` entities into row-banded top-to-bottom/left-to-right reading order, `ROW_BAND_PX =
24` tolerance) and `nextFocusId` (1-D walk forward/backward through that order, wrapping at either
end). `web/src/keyboard/useRovingFocus.ts` wires this to real DOM entities via a `data-entity-ref`
attribute (added to `EntityNode.tsx` for Graph view and every clickable button in
`SwitchFaceplate.tsx`/`SwitchView.tsx` for Switch view) — reads live `getBoundingClientRect()`
geometry rather than any stored coordinate, so it works identically against whichever DOM renderer
is currently mounted (v1 today; T-901/T-905's canvas a11y bridge automatically once that lands, per
the task card — no rework needed here since this hook only ever looks at the DOM, not at
`toFlowElements`'s output directly). One delegated `keydown` listener on the containing wrapper
(`TopologyPage.tsx`'s `entityContainerRef`, wrapping whichever of Switch/Graph is mounted): arrow
keys move focus, Enter calls `onActivate` (wired to the same `handleNodeClick` a pointer click
uses — `event.preventDefault()` on Enter also suppresses Switch view's native `<button>`
double-activation that would otherwise fire from the browser's own default Enter-on-button
behavior).

**Per-page verb registration** (all gated on the same write-capability check each page's own UI
already uses, so the palette never offers a write a read-only session can't perform):
- **Topology** (`TopologyPage.tsx`): one "Edit `<entity>` on `<node>`" verb per bridge/bond/VLAN/
  physnic the inspector already offers an Edit button for (`editorKindForInventoryKind`). The node
  suffix disambiguates identically-named entities across nodes (e.g. every node's own "vmbr0") —
  added after noticing the three-node-vlan fixture has exactly that collision.
- **SDN** (`SdnPage.tsx`): "New VLAN zone" — jumps straight into the VLAN wizard rather than the
  zone-type picker grid. Required a small, additive change to `ZoneWizardPicker.tsx`: a new optional
  `initialActive?: WizardKind` prop (exported `WizardKind`) that the picker applies on its own
  `open` transition; the toolbar's existing "+ New zone (guided)" button passes `undefined` and is
  unaffected (verified against the existing `user-guide-tasks.spec.ts` e2e coverage of that button).
- **Changesets/drafts** (`ChangesetDrawer.tsx`): "Open drafts" → `setDrawerOpen(true)`. This
  component is mounted once, app-wide (not route-scoped, per its own existing doc comment), so the
  verb is reachable from every page, not just wherever a draft originated.
- **Simulator** (`SimulatorPage.tsx`): "Simulate path from `<entity>`" — dynamic, registered only
  while the shared topology-store selection points at a traceable entity (`isTraceableEntityKind`,
  reusing `traceLink.ts`'s existing guest-nic-only rule); `perform()` sets this page's own `src`
  endpoint directly (no navigation needed, since the verb is only live while already on
  `/tools`).
