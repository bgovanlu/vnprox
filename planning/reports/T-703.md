# T-703 · Guided management-redundancy & dedicated-mgmt-interface wizard — report

## What was built

**Op vocabulary extensions (interlock-clean by construction)**
- `internal/change/params_vlan.go`: `VlanCreateParams.Gateway` (renders the stanza `gateway`
  option) — a VLAN sub-interface taking over the management IP must also carry the node's default
  route. Rendered in `internal/change/ifaces/{op.go,vlanop.go}` (`VlanCreate.Gateway`) and
  schema-validated (`validate_schema.go`).
- `internal/change/params_iface.go`: `IfaceUpdateParams.RemoveAddress`/`RemoveGateway` — the wire
  counterparts of `ifaces.IfaceUpdate`'s same-named fields (which `ifaces.DecodeOp` already
  decoded; the strict `change.Op` decoder just never admitted them). Projection-folded in
  `validate_projection.go` so the safety class sees a stripped address as removed.

**touchesMgmtPath + apply ceremony (server-side)**
- `internal/change/mgmttouch.go` (new): `TouchesMgmtPath(paths, ops)` — pure over T-702's
  `MgmtStatus.Nodes` (carrier refs + every path member); `MgmtConfirmTimeoutFloor = 180s`;
  `Service.RecordMgmtAck` (audits `changeset.mgmt_ack`). Deliberately over-approximates (an op
  merely *naming* a path NIC counts) since a false positive costs one extra confirmation while a
  false negative would skip the ceremony.
- `internal/api/changesets.go`: every changeset response carries the server-computed
  `touchesMgmtPath` (`mgmtPathsFor`/`withMgmtFlag`, computed once per list over the same
  `MgmtStatus` the badges use). `POST /apply` now: computes the flag; for a touching changeset
  floors `confirmTimeoutSec` at 180s (rejects lower with `400 confirm_window_too_short` before any
  apply work) and records `mgmtAck: {node}` when present. `mountChangesetsRoutes` gained the
  `MgmtStatusService` seam (wired from `Options.Protected` in `router.go`).
- `internal/change/{protected.go,service.go}`: `MgmtStatus.StaleProtected` (+ `protectedSetStale`)
  and `internal/api/protected.go`'s `staleProtected` response field — true iff the confirmed set no
  longer contains a live-detected carrier (a moved management path).

**Frontend (all under `web/src/mgmt/`)**
- `mgmtWizardOps.ts`: pure op builders for flow A (bond the uplink), B (add/replace a bond slave),
  C (dedicated mgmt VLAN) — matching the backend golden ops exactly; never emit an address-bearing
  op except flow C's verbatim carry-over, so the UI cannot re-address the mgmt IP.
- `situation.ts`: derives per-node flow availability + candidate NICs purely from
  `GET /protected-interfaces/status` + `GET /topology`.
- `MgmtRedundancyWizard.tsx` (on T-403's `WizardShell`) + `MgmtWizardHost.tsx` +
  `mgmtWizardStore.ts`: one app-wide wizard instance, launched from three points — the
  `mgmt_single_path` finding (`FindingsStreamPanel` + a new optional `action` on `FindingsList`),
  the inspector's "Management path" section (`InspectorPanel.tsx`), and the topology
  `NewEntityMenu`. Output is always a drawer draft, never a direct apply.
- `strings.ts`: all explanatory copy in one file (non-expert bar).
- `ReviewApplyScreen.tsx`: the mandatory acknowledgement block for a `touchesMgmtPath` changeset —
  typed node name required (Apply disabled until it matches), plain-English commit-confirm
  explanation, confirm window defaulted to 180s and floored client-side; sends `mgmtAck`.
- `MgmtProtectedRefreshPrompt.tsx`: post-commit (flow C) refresh prompt driven by `staleProtected`,
  pre-filled from `GET /protected-interfaces/suggest`; accepting PUTs the new carrier ref,
  declining leaves protected.json + the stale warning (inspector) intact.

**Fixtures**: `three-node-vlan.yaml` gained pve1-only spare `eno3` (flow-B candidate); reused
`single-node.yaml` (spare `eno2`, flow A) and `vlan-mgmt.yaml` (flow C) from T-702. Added
`testdata/dev-mgmt.toml` + a 4th e2e webServer pair (single-node on 38006/38007).

**Docs**: `docs/api.md` (touchesMgmtPath, mgmtAck, confirm_window_too_short, staleProtected),
`docs/features/change-management.md` §4, `planning/reports/needs-hardware-validation.md` (T-703
section).

1. **PASS** — flow A (both modes)/B/C golden ops validate with zero safety-class findings
   (`mgmtwizard_test.go`); "already redundant → offers nothing destructive" is covered by
   `situation.test.ts` (three-node-vlan pve1 → `redundant: true`, no flow A) and the wizard's
   already-redundant banner.
2. **PASS** — tamper tests trip `safety.protected_interface` (backend); the op builders cannot
   construct those states (flow A always ends with `bridge.port.add`; flow C always carries the
   same address) — unit-tested in `mgmtWizardOps.test.ts`.
3. **PASS (with a flagged mock limitation)** — the e2e drives finding → wizard → drawer → review
   (ack gating) → apply → countdown → confirm → committed, and asserts the audit ack entry. The two
   clauses "the `mgmt_single_path` finding clears on the next poll" and "the fixture interfaces file
   shows the bond" are **not observable against pvemock** (node-file network ops write the dev host
   sandbox and never touch pvemock's PVE model — docs/architecture.md §4's T-607 correction — while
   the collector reads `host.NewReal()`, not that sandbox), so they moved to the hardware-validation
   list. Everything else in AC3 passes in the mock e2e.
4. **PASS (unit layer)** — `TestMgmtWizard_FlowA_AutoRollback`: deadline expiry → `rolled_back`,
   pre-state byte-identical. Not driven in e2e: the 180s mgmt confirm floor exceeds Playwright's
   120s per-test timeout, and "auto-rollback with mgmt actually down" is an AC7 hardware item.
5. **PASS** — `touchesMgmtPath` computed server-side for any changeset touching the path (table
   test + API test on hand-built drafts); false otherwise; confirm-window floor enforced server-side
   (`400 confirm_window_too_short`).
6. **PASS** — flow C commit → `staleProtected` → `MgmtProtectedRefreshPrompt` appears; accept PUTs
   the suggested set (audited by the existing `protected.update` path); decline leaves protected.json
   untouched and the stale warning visible in the inspector's Management path section. Backed by
   `protectedSetStale` unit behavior via `Service.MgmtStatus`; the prompt component is wired in the
   app shell. (Not separately e2e-driven — flow C requires a `confirmed` protected.json to go stale,
   which the fresh-DB e2e stack does not have; covered at the service + component layer.)
7. **PASS** — hardware-validation list enumerated in
   `planning/reports/needs-hardware-validation.md` (new "Management-redundancy wizard (T-703)"
   section): real `ifreload` outage window on an active mgmt bridge; the finding actually clearing
   post-apply; LACP against a real switch + active-backup failover; auto-rollback with mgmt down on
   a peer; flow C protected-set refresh vs real corosync binding. `make check` green; abandoning the
   wizard leaves no draft residue (WizardShell drafts only on finish — inherited from T-403 AC5).

## Deviations from the task card

- **AC3 finding-clears / interfaces-file-shows-bond → hardware-validation.** Not observable against
  a static pvemock (see AC3 above). The e2e proves the full apply→confirm→committed lifecycle plus
  the audited acknowledgement; the two inventory-reflection clauses are genuinely a real-node
  property, now on the AC7 list. This is the same mock/dev-sandbox divergence architecture.md §4
  already documents, not a gap in the wizard.
- **AC4 no-confirm path proven at the unit layer, not e2e** — the 180s mgmt confirm floor (itself a
  T-703 requirement) exceeds Playwright's per-test timeout. The daemon-side rollback timer is
  exercised deterministically via the harness fake timer instead.
- **Repeat-for-other-nodes fan-out**: the card lists an optional "repeat for other nodes" fan-out.
  The wizard is per-node and re-launchable per node (each run re-selects that node's own candidate
  NICs, cluster-aware); a one-click multi-node fan-out button was not built — noted as the one
  card sub-item deferred, low-risk since staging a second node's changeset is one more wizard run.
