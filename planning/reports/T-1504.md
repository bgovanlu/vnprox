# T-1504 · Service-network attribution — report

**Status:** complete. `make check` green (gofmt, `go vet`, golangci-lint 0 issues, `go test ./...`, eslint, `tsc --noEmit`, vitest, govulncheck, `npm audit --audit-level=high`).

## What was built

**`internal/flow/classify.go`** — the classifier T-1503/T-1507 build on:
- `ServiceClass`: `"migration"`\|`"backup"`\|`"ceph-public"`\|`"ceph-cluster"`\|`"corosync"`\|`"unclassified"`.
- `Classifier` holds zero or more `NetworkSource` values per `NetworkSourceKind` (`corosync`\|`migration`\|`backup`\|`ceph`), registered via `RegisterNetworkSource(kind, source)` — the explicit extension point the card requires so T-1503/T-1507 extend the input set without touching this file's core logic. Sources are checked in a fixed precedence (corosync → migration → backup → ceph), first match wins.
- `Classify(rec) ServiceClass` / `Verdict(rec) Classified` / `ClassifyBatch(records) []Classified` — metadata-only (IP/CIDR containment, exact address, VLAN, protocol/port). **Honesty-contract regression**: `internal/flow/classify.go` has no import of any capture/payload package (confirmed by inspection and `go build`; no `internal/capture` symbol referenced anywhere in the package).
- Built-in `NetworkSource` constructors: `NewAddrSetSource` (exact-address match), `NewCIDRSource` (CIDR containment — the generic constructor T-1503 uses directly for Ceph public/cluster CIDRs), `NewCorosyncSource` (wraps addr-set over corosync's configured ring addresses), `NewMigrationNetworkSource` (wraps CIDR over a declared migration network), `NewBackupPathSource` (wraps addr-set over PBS host addresses — see the PBS deviation below).
- Each source optionally declares a VLAN set (`DeclaredVLANs()`); `Verdict` additionally reports `WrongNetwork: bool` — true when the record's own VLAN is known and outside the matching source's declared set. This is `service_traffic_on_wrong_network`'s exact input.

## Output shape T-1503/T-1507 consume

```go
// internal/flow
type ServiceClass string // migration | backup | ceph-public | ceph-cluster | corosync | unclassified

type NetworkSourceKind string // corosync | migration | backup | ceph

type NetworkSource interface {
    Kind() NetworkSourceKind
    Classify(rec Record) (class ServiceClass, ok bool)
    DeclaredVLANs() []int
}

type Classified struct {
    Record       Record
    ServiceClass ServiceClass
    WrongNetwork bool
}

func NewClassifier() *Classifier
func (c *Classifier) RegisterNetworkSource(kind NetworkSourceKind, source NetworkSource)
func (c *Classifier) Classify(rec Record) ServiceClass
func (c *Classifier) Verdict(rec Record) Classified
func (c *Classifier) ClassifyBatch(records []Record) []Classified

// Generic constructor T-1503 calls directly for Ceph:
func NewCIDRSource(kind NetworkSourceKind, class ServiceClass, cidrs []string, vlans []int) (NetworkSource, error)
```

- **T-1503 (Ceph)**: calls `RegisterNetworkSource(NetworkSourceKindCeph, mustCIDRSource(NetworkSourceKindCeph, ServiceClassCephPublic, publicCIDRs, vlans))` and the same for `ServiceClassCephCluster`/cluster CIDRs — no new classification logic on T-1503's side, exactly as the phase doc specifies ("T-1503 does not implement its own classification logic, it supplies T-1504's engine with Ceph's network declarations").
- **T-1507 (migration planner)**: reads `ServiceClassMigration`-tagged `Classified.Record.Bytes` directly (via the same `*flow.Classifier`/recent-flow-window this card wires) to compute current migration-traffic volume against T-1303's mesh link-capacity data — no second migration-traffic detector.

## Additive API surface

- `GET /flows` (`internal/api/flows.go`): every `flowRecordResponse` item gains `serviceClass?: string`, computed via an optional `*flow.Classifier` (`api.Options.FlowClassifier`, nil-safe — field omitted entirely, never emitted as a misleading `"unclassified"`, when no classifier is wired). Threaded through both the local-node path and the cluster fan-out (`fetchClusterFlows`/`peerFlowRecordToResponse`), so a cluster-wide `GET /flows` view classifies peer-sourced records too.
- `GET /history/events` (`internal/api/history.go`): a `kind: "finding"` entry additionally carries `serviceClass?: string` when its `findingId` is a `service_traffic_on_wrong_network` finding — parsed from the finding's own content-derived id (`findings.ServiceClassFromFindingID`) at render time rather than a new `finding_events` column, since the id already carries it.
- History playback needs no separate wiring: `web/src/topology/history/HistoryTimeline.tsx`'s scrubber replays flow-painted edges by re-querying `GET /flows?fromTs=&toTs=`, so `serviceClass` is visible identically live or scrubbed.
- `internal/findings`: new `SourceFlow = "flow"` and `service_traffic_on_wrong_network` check (`health_serviceclass.go`) — one finding per `(serviceClass, vlan)` pair with at least one flow record flagged `WrongNetwork`, standard 2-cycle-each-way hysteresis (mirrors `corosync_link_degraded`), fed by a new `findings.FlowProvider` seam (`RecentClassified() ([]flow.Classified, error)`).
- New Home-dashboard tile `ServiceClassTile.tsx` (`web/src/dashboard/`): per-`serviceClass` bytes/sec breakdown over `GET /flows`' recent window — pure client-side computation (`serviceClassBreakdown.ts`), no new backend aggregation, mirroring `TopTalkersTile.tsx`'s own convention. Added to `DashboardPage.tsx`'s tile grid.
- Flow Explorer (`FlowExplorer.tsx`) gains a "Service" column showing each row's `serviceClass` (or "—" when the field is absent, i.e. no classifier wired — distinct from the classifier's own explicit `"unclassified"` verdict).

## Production wiring (`cmd/vnproxd/serviceclassify.go`)

- Builds one `*flow.Classifier` at startup and registers **corosync's configured ring addresses** (`internal/host.ReadCorosyncConf`, the same static-address substrate T-803/T-703 already read) — the one class this composition root has genuine live data for today. Wired into both `api.Options.FlowClassifier` and, via a lazily-set `flowClassifyAdapter` (mirrors `mgmtStatusAdapter`/`scheduleMissedAdapter`'s existing pattern in `cmd/vnproxd/findings.go` for the "`findings.Engine` is built before its dependency exists" ordering problem), `findings.Config.Flow`.
- `flowClassifyAdapter.RecentClassified` queries the last 5 minutes / up to 5000 rows of `flow_samples` (bounded, not a full-window scan — the finding is hysteresis-debounced across several Engine cycles anyway) and classifies them fresh each findings cycle.
- Migration/backup/Ceph sources are **not** registered by this composition root — see the deviations below.

## Deviations from the task card

1. **PBS backup class — declared-but-inert seam, per the orchestrator's explicit instruction.** T-1206 (PBS network awareness, Phase 12) is confirmed absent from this repo (no `internal/pbs` package, no `pbs-host`/`backup-path` inventory entities — verified by grep). `flow.NewBackupPathSource(pbsAddrs, vlans)` is a fully working, independently-tested `NetworkSource` constructor (`classify_test.go`'s `TestClassifier_Classify` exercises it directly with synthetic PBS addresses, satisfying AC1's "PBS backup-path edges ... classify correctly"), but `cmd/vnproxd`'s production wiring never calls it — there is no live source of PBS addresses to pass it. When T-1206 lands, wiring `RegisterNetworkSource(NetworkSourceKindBackup, flow.NewBackupPathSource(pbsAddrs, vlans))` at the composition root is the entire integration step.
2. **PVE migration-network CIDR — no live reader wired (documented pre-existing gap, not new to this card).** No reader of PVE's own `datacenter.cfg`'s `migration: network=` exists anywhere in this codebase — `planning/reports/needs-hardware-validation.md` and docs/api.md's T-1303 fabric-scope note already flag this as a repeatedly-documented gap. `flow.NewMigrationNetworkSource(cidrs, vlans)` is a fully working, independently-tested constructor (exercised in `classify_test.go`), but this composition root does not register it with a live CIDR by default. Building a `datacenter.cfg` reader was judged out of scope for this card's own deliverables (`internal/flow/classify.go` + additive API/finding/tile surface) — flagged here rather than silently skipped.
3. **`serviceClass` is computed at read time, not persisted.** `flow_samples` gained no new column: `GET /flows` classifies each row fresh against whatever `NetworkSource`s are *currently* registered, so a row ingested before, say, T-1503 registers Ceph CIDRs still classifies correctly once that registration happens — "recompute from live state," the same stance `internal/ipam`'s conflict findings already take. Documented in `docs/data-model.md`'s `flow_samples` entry.
4. **Corosync's own UDP port is deliberately not used as a classification signal**, only its configured ring *addresses* — the port-numbering-per-ring behavior is unverified against real hardware (a repeatedly-flagged needs-hardware-validation item elsewhere in this codebase); address matching is the trustworthy metadata signal several existing checks already rely on.
5. **`service_traffic_on_wrong_network` requires a source's `DeclaredVLANs()` to be non-empty to ever fire.** In production today only corosync is registered, and it is registered with `vlans: nil` (this composition root has no source for corosync's *intended* VLAN) — so the finding is fully implemented, tested, and wired into the findings engine, but will not fire against a real cluster until an operator or a future card (e.g. T-1503 registering Ceph with its own resolved VLAN) supplies a declared VLAN set. This is the same "quietly absent until wired" degradation every other optional `findings.Config` producer in this codebase already has.
