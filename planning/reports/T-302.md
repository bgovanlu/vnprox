# T-302 · LLDP collection, switch merging, ports table

## What was built

**`internal/host`** — `lldp.go`: `ParseLLDP([]byte) ([]LLDPNeighbor, error)`, a defensive parser for the real `lldpctl -f json` schema (nested `lldp[].interface[].{chassis,port}`, lldpd's well-known single-item-collapses-to-bare-object inconsistency handled for every list field, CDP-decoded neighbors via the `via` field, MAU/speed strings, PVID + tagged VLANs, mgmt IPs), plus a fallback for the flat simplified array shape `internal/pvemock`'s fixtures/`inventory`'s pre-T-302 code already used (kept so no other package needed touching). Never panics (recover-wrapped; malformed individual entries are skipped, not fatal). `netlink_linux.go`'s `Real.LLDP` now wraps a missing-binary exec error with `ErrLLDPUnavailable` so callers can distinguish "never installed" from "installed but erroring". `lldp_install_linux.go`/`_other.go`: `Real.InstallLLDPD` (fixed-argv `apt-get install`/`systemctl enable --now`) backing the guided-install flow.

**`internal/inventory`** — `LldpNeighbor` gains `Protocol`, `ChassisIDType`, `ChassisDescr`, `MgmtIPs`, `PortIDType`, `TaggedVLANs`, `SpeedMbps`, `SpeedDescr`, `LastSeen` (existing `VLAN`/`MgmtIP`/`TTL` etc. field names unchanged). `FromLLDP` now delegates parsing to `host.ParseLLDP` and takes a `now time.Time` for `LastSeen`. New `RetainStaleLLDP(snap, node, fresh, now)`: folds forward previously-seen neighbors a poll's raw output omitted but that haven't crossed the 10-minute drop threshold — without this, `Graph.ApplyPoll`'s normal per-source scope reconciliation would delete a neighbor the instant one poll missed it, defeating the whole staleness lifecycle. `LastSeen` is deliberately excluded from `fieldMap()` so it doesn't spam `topology.delta` every poll (same reasoning as counters staying out of the entity model).

**`internal/topology`** — `switches.go`: chassis-ID merging into synthetic `KindSwitch` map nodes + `EdgeLLDPPort` edges from each contributing `PhysNic`, additive over the pre-existing per-neighbor `lldp-neighbor`/`lldp-adjacent` rendering (left untouched — see Deviations). Implements the grey-at-2×TTL / drop-at-10min lifecycle via a new `Filter.Now` clock-injection field (zero value = `time.Now()`, no production behavior change). `vlancheck.go`: `VlanFindings(snap)` walks NIC→(bond→)bridge edges and compares expected VIDs against advertised PVID+tagged, emitting one finding per (bridge, neighbor) pair with codes `vlan_cross_check_ok`/`_missing_on_switch`/`_missing_on_bridge`. `ports.go`: `Ports(snap, now)` / `PortsCSV(rows)` — the flat table keeps stale/dropped rows (tagged `stale`) that the map itself excludes.

**`internal/api`** — `lldp.go`: `GET /lldp`, `GET /lldp/vlan-check`, `GET /ports` (+ `?format=csv`), netRead-gated. **`docs/api.md`** updated with these three routes (flagged addition per docs/development.md's definition-of-done #4 — `/lldp`'s shape was undocumented, `/lldp/vlan-check` and `/ports` didn't exist in the contract at all).

**`internal/peer`** — `POST /api/peer/host/lldp/install` (confirm-gated, nil-safe `LLDPInstaller` dependency) and a matching `Client.InstallLLDPD`. Did not touch signing/auth/replay logic.

**Wiring**: `cmd/vnproxd/server.go` passes `LLDP: topoSvc` into the router and `LLDPInstaller: realHost` into the peer server.

- `internal/api`, `internal/peer`: router-level auth-gating + happy-path tests for the three new routes and the peer install route (confirm-required, unconfigured→503, installer-error→500).
- `make check` green end-to-end (gofmt, go vet, golangci-lint — 0 issues after fixing fieldalignment/package-comment findings my own changes introduced —, eslint, tsc, `go test ./...`, vitest 209/209, govulncheck, npm audit). `web/` was untouched; `npm ci` had never been run in this fresh worktree, so it was run once to make `make check` executable at all.

## Deviations from the task card, with reasons

1. **Cluster fan-out ("via peer API cluster-wide") deferred to T-303.** T-303's own card explicitly owns "host-poller extension: local `host.Reader` for self, peer-API-backed reader for every other node, uniform ingestion into inventory" and "`GET /lldp` ... fan out likewise" — and does not depend on T-302. I built the local 30s collector's LLDP handling correctly (it already existed from an earlier collectors task, T-104; T-302 replaced its flat-only parsing with the real defensive parser and added the retention/staleness layer) so it's ready for T-303 to extend to peers without further change here.
2. **Switch merging is additive, not a replacement, on the map.** The pre-existing per-`LldpNeighbor` node + `lldp-adjacent` edge rendering (owned by T-106/T-107, pinned by several of their tests) is left exactly as-is; new `KindSwitch` nodes + `EdgeLLDPPort` edges are added alongside it. This satisfies AC1 without risking those other tasks' test suites (I did have to update three of their *count* assertions in `project_test.go` since the total node/edge count legitimately grew — logic unchanged, only the new switch nodes/edges added).
3. **`internal/collect` was touched**, despite not being in the explicitly-named package list. It's the concrete implementation of architecture.md's "Collectors" component and already owned `lldpPollOnce`/`RunLLDPLoop` from an earlier task; T-302's staleness-retention requirement (a neighbor must survive being momentarily absent from one poll) is structurally a collector-level concern (it needs "previous snapshot + fresh poll → what to submit to `ApplyPoll`"), so `lldpPollOnce` now calls `inventory.RetainStaleLLDP` and passes `time.Now()`. The change is two lines plus a doc comment; no other collect behavior changed.
4. **Guided lldpd install is scoped down.** Built and tested: the host-level installer, the confirm-gated peer route, and its client method. Not built: a user-facing `POST /api/v1/lldp/install` endpoint with audit-log wiring and multi-node fan-out — that layer isn't gated by any T-302 acceptance criterion (AC4 only requires the *degraded state* render correctly, which is tested), and a real "changeset-like confirmation" UX + cluster-wide audit trail fits naturally alongside T-303's peer-write orchestration and the frontend work, rather than being invented ad hoc here. Flagging for whichever task picks up the UI.
5. **`fieldalignment -fix`** (part of getting `golangci-lint` to 0 issues) reordered struct fields across several files, including one file I hadn't otherwise touched (`internal/api/topology_test.go`, whose anonymous test-case struct embeds `topology.Filter` and was affected transitively by my `Filter.Now` addition) — fixed by converting that struct literal to named fields. It also touched `internal/host/ethtool_linux.go`'s `ifreqData` (a kernel-ABI struct explicitly marked `//nolint:govet` for fixed layout); I reverted that one file specifically since ignoring a deliberate ABI-layout nolint would be a correctness bug, not a style fix.
6. **New API routes not in the original `docs/api.md` contract**: `/lldp`'s response shape was undocumented, and `/lldp/vlan-check`/`/ports` didn't exist at all. Added both to the doc in this change per docs/development.md's definition-of-done #4.

## Needs hardware validation

`Real.LLDP`'s exec path (`TestReal_LLDP`, pre-existing) skips cleanly on this sandbox since lldpd isn't installed; the real nested-JSON parser has only been validated against hand-constructed fixtures matching lldpd's documented schema, not a live `lldpctl -f json` capture. Recommend a next-task or pre-release pass capturing real output from an actual lldpd instance (ideally including a genuine CDP-decoded neighbor) into `internal/host/testdata/lldp/` to close that gap.

## Anything the next agent must know

- `host.ParseLLDP` is the single source of truth for LLDP JSON parsing now; `inventory.FromLLDP` no longer parses JSON itself. If T-303's peer-backed host reader ever needs to re-parse a peer's raw LLDP bytes, reuse `host.ParseLLDP` rather than re-implementing.
- `inventory.RetainStaleLLDP` must be called before every `ApplyPoll(SourceHostLLDP, ...)`, local or (once T-303 lands) peer-scoped — skipping it silently reintroduces the "neighbor vanishes on one missed poll" bug the whole staleness lifecycle exists to prevent.
- `topology.Filter.Now` is the test seam for anything staleness-related; production code should never set it (defaults to `time.Now()`).
- The ports table (`topology.Ports`) intentionally does **not** apply the map's layer/node/vlan filters — it always returns every `LldpNeighbor` in the graph. If a future task wants a filtered ports view, add filtering at the `internal/api` handler layer rather than changing `Ports`' contract.
