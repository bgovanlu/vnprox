# T-1601 · Flow baselining & anomaly findings — completion report

## What I built

A new `internal/baseline` package that learns per-guest/per-segment traffic
baselines from the retained flow window and detects explainable deviations,
wired into the existing findings engine as a new `source: "baseline"` producer,
persisted through a new app-owned `baseline_profiles` store table.

### `internal/baseline` (new package)
- `Learn(records, ref, window) Profile` — a statistical summary per inventory
  `Ref`: top talkers (peer→bytes), the observed **service-port** set
  (destination ports only; ephemeral source ports are deliberately excluded so
  a client's random high port never reads as a "new port"), the observed
  peer-subnet set (/24 IPv4, /64 IPv6 aggregation), and a per-hour-of-day
  byte-volume histogram with mean/stddev computed over the per-wall-clock-hour
  totals (scale-consistent with detection).
- `Detect(profile, recent, cfg) []Anomaly` — three deviation classes
  `new_port` / `volume_spike` / `new_subnet`. Each `Anomaly` carries
  `{BaselineWindow, BaselineValue, ObservedValue, DeviationFactor}` — the
  machine-checkable "names its baseline and the deviation" contract. An empty
  baseline raises nothing (cold-start silent); feeding a profile's own training
  window back in raises nothing (per-hour ratios never reach the spike
  multiple; every port/subnet already known).
- `Profile`/`Corpus` JSON (de)serialization (`Marshal`/`Unmarshal`,
  `ParseCorpus`).
- **Fixture family** under `internal/baseline/testdata/`: `clean_injected_corpus.json`
  (clean 14-day baseline + one injected anomaly of each class) and
  `noise_corpus.json` (pure noise, no anomaly). Both are deterministic and
  regenerable via `BASELINE_GEN=1 go test -run TestGenerateCorpora`; the shared
  `Corpus`/`ParseCorpus` type is the single fixture format T-1602's planner
  tests will read verbatim.

### `internal/store` (new table + repo)
- Migration `0025_flow_baselines.sql` (**numbered 0025 as required**;
  `kv_test.go` schema-version assertion bumped 24→25).
- `baseline_profiles` (ref PK, profile_json, window_start/end, updated_at) with
  `BaselineProfileRepo`: `Put` (upsert-by-ref), `Get`, `List`, `Count`, `Prune`,
  `PruneRetention`, and `RunPruneLoop` mirroring `MetricSampleRepo.RunPruneLoop`.
  Default retention 90 days — far longer than `flow_samples`' window, so a
  baseline outlives the raw flows it summarizes.

### `internal/findings` (new producer)
- `SourceBaseline` (`"baseline"`), checks `new_port|volume_spike|new_subnet`.
- `adapt_baseline.go`: `BaselineProvider` seam + `checkBaselineAnomalies`, with
  standard 2-cycle firing hysteresis (same debouncer as
  `service_traffic_on_wrong_network`). Findings are `severity: warning`,
  `fixable: false`, `docsLink` set, `refs` = the affected guest/segment ref,
  and `detail` a plain-English rendering naming baseline/observed/deviation
  (never a bare "anomalous"). Wired into `Config`/`Engine`/`Findings()`.

### `cmd/vnproxd` (wiring)
- `baseline.go`: `baselineService` — the scheduled learn job (`RunLearnLoop`,
  default 24h, run-once-then-tick), the `findings.BaselineProvider` adapter
  (`RecentAnomalies` runs `Detect` over stored profiles + a bounded recent
  `flow_samples` window each findings cycle), and bounded paginated flow scans.
- `server.go`: builds the repo + service before `setupFindings`, points it at
  `flowRepo` after `setupFlows` (mirrors `flowClassifyAdapter`'s two-step
  wiring), and registers the learn loop + retention prune loop as supervised
  run-group actors.
- `[baseline]` config section (`profile_retention_days` default 90,
  `learn_interval_hours` default 24).

### Docs
- `docs/api.md`: `baseline` added to the `GET /findings` source enum + a
  dedicated `source: "baseline"` paragraph (checks, honesty/non-IDS contract,
  id scheme, hysteresis).
- `docs/data-model.md`: `baseline_profiles` CREATE TABLE + prose entry (app-owned
  summary data that outlives `flow_samples`; anomalies recomputed, not stored).

## Testing (how, and mapping to acceptance criteria)
Table-driven Go tests, `internal/baseline/testdata` fixtures:
- **AC1** `TestDetect_BaselineNeverFlagsOwnTrainingData` — Learn then Detect on
  the same flows raises 0, for both corpora.
- **AC2** `TestDetect_InjectedAnomalies` (structured fields) + findings-side
  `TestBaselineAnomalies_Rendering` (check==class, explainable detail, stable
  id, 2-cycle hysteresis).
- **AC3** `TestDetect_VolumeSpikeThreshold` — synthetic step-change series,
  configured multiple ∈ {5×,10×,20×}, fires only once the multiple is crossed.
- **AC4** `TestBaselineProfileRepo_PruneRetention` /
  `TestBaselineProfileRepo_PruneCadenceMatchesMetricSamples` — age prune on the
  metric_samples tick cadence; default window dwarfs any flow window.
- **AC5** `TestDetect_ColdStartSilent` — no history → empty profile → no
  anomalies.
- Plus `TestLearn_Summary` (port/subnet/talker/hour stats) and
  `TestProfile_MarshalRoundTrip`.

## Deviations from the task card
- None substantive. The card's `[baseline] profile_retention_days` is
  implemented; the learn-window "days" is a package constant
  (`baseline.DefaultLearnWindowDays` = 14) rather than a config knob — the
  window is capped in practice by `flow_samples`' own retention anyway, and the
  `[baseline]` section carries retention + learn cadence. Easy to promote to a
  config field later if wanted.
- The `new_port` observed-port signal keys on the **destination** (service)
  port only; ephemeral source ports are excluded by design (documented in the
  package + api.md). This is the honest reading of "a new outbound port from a
  DB guest" and avoids swamping the signal with random client ports.
