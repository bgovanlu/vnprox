# T-1606 · Capacity forecasting — completion report

## What was built

The network-intelligence arc's **one deliberate retention extension**: a bounded,
downsampled long-term aggregate store plus a linear-trend forecast producer.

### Store & schema
- **Migration `internal/store/migrations/0026_capacity_samples.sql`** — new
  `capacity_aggregates` table `(ref, kind, bucket_at, avg_utilization,
  max_utilization, created_at)`, PK `(ref, kind, bucket_at)` so a day's rollup

- **`internal/store/kv_test.go`** — schema-version assertion bumped `24 → 26`.

### Forecast engine (`internal/capacity`, stdlib-only)
- `Forecast(aggregates, horizonDays) Projection{CrossesAt *time.Time,
  Confidence}` — OLS linear fit over daily `MaxUtil`; `CrossesAt` is nil for a
  flat/decreasing trend or a crossing beyond the horizon (no false-positive on
  stable utilization). Confidence is the fit's R².
- `Analyze(aggregates, horizonDays) []ForecastFinding` — groups by (ref, kind),
  forecasts each, emits a plain-English detail naming the projected exhaustion
  date and horizon. Checks `capacity_link_forecast` / `capacity_ipam_forecast`.
- `LinkDailyUtil` / `PoolUtil` — the pure utilization math (counter-delta rate
  vs. link speed; allocated/total).
- `RollupJob` (supervised, `Run`/`RunOnce`) over `BucketSource`/`Sink` seams —
  computes yesterday's UTC bucket, restart-safe/idempotent (upsert-keyed).

## Deviations / notes for the next agent
- **Link rollup covers `PhysNic`s only.** Utilization needs a negotiated
  `SpeedMbps`, which resolves (per `internal/inventory` ownership rules) only
  for host-netlink physical NICs. Bond-aggregate speed (sum of active slaves,
  as `metrics/linkmeta.go` computes for the live sampler) is a deliberate,
  documented future refinement rather than a silent approximation — uplink
  PhysNics are the capacity signal a forecast cares about today. VLAN
  sub-interfaces and bridges are not rolled up.
- **No frontend deliverable.** T-1606's card lists no `web/` component or AC;
  none was added. The forecast findings surface through the existing unified
  findings stream UI unchanged.
- **Rollup vs. 24h prune timing.** `RunOnce` computes the just-completed UTC
  calendar day; with `metricPruneInterval = 1h` and a 24h `metric_samples`
  window, running shortly after midnight captures essentially the whole prior
  day. The rollup actor runs once at startup and daily thereafter.
- **`GET /capacity/export` is netRead-gated** and uses `time.Now` for the
  window bound (injectable in the handler for tests).
- Needs no hardware validation — everything is exercised against seeded
  fixtures and the store.
