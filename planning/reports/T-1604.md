# T-1604 · Failure impact simulation core — completion report

## What I built

A new **`internal/failsim`** package: a pure, static "what breaks if X dies?"
simulator over the live inventory snapshot, plus its two API routes, the
T-1103 scheduler pre-flight hook, and docs.

### Core (`internal/failsim`)
- **`Simulate(Input, target) Impact`** — removes `target` from a *copy* of the
  inventory graph (`rebuildExcluding`, re-ingesting survivors through a real
  `inventory.Graph` so the resolver recomputes bridge ports / bond slaves /
  VLAN parents / guest attachments exactly as a live poll would) and recomputes:
  - `DisconnectedGuests` — guests with a live uplink pre-failure and none post.
  - `StrandedVlans` — SDN vnets that lose their underlay uplink everywhere.
  - `MgmtPathLoss` — nodes losing their management path, computed by re-running
    the **shared** resolver (`topology.ResolveMgmtPaths` via
    `change.DetectProtectedRoles`) on the post-failure snapshot — the same
    function `GET /protected-interfaces/status` and the T-703 interlock use.
  - `QuorumRisk` — reachable corosync voters dropping below `floor(N/2)+1`,
    computed from the corosync ring topology.
  - `CephRisk` — an OSD-hosting node isolated from Ceph's public/cluster
    network, reusing T-1503's `ceph.Project` read model.
  - `NotEvaluated` — the honesty channel (see soundness boundaries below).
- **`Inventory(Input) []SPOFEntry`** + **`Score`** / **`ScoreInventory`** — the
  SPOF inventory backing the dashboard tile; enumerates nodes, bonds, bridges,
  uplink NICs, LLDP-discovered switches and (where supplied) WireGuard tunnels,
  keeping only elements with a nonzero *known* impact.
- **`Preflight(Input, refs) Impact`** + **`PreflightUnsafe(Impact)`** — the
  worst-of-touched-refs verdict and the additive veto decision (quorum risk or
  mgmt-path loss).
- **`honesty.go`** — the grep-able dimension→evaluated inventory (AC7 / T-503
  AC3 convention), exported via `HonestyInventory()`.

### Switch support
LLDP-discovered switches are first-class SPOF targets (a `KindSwitchPort` ref
keyed by chassis id); removing one knocks out every NIC facing that chassis —
the "one switch takes down both corosync links" exit-demo scenario, and how the
quorum-risk case is exercised.

### T-1103 pre-flight hook (`internal/change`)
- New `ImpactPreflighter` seam + `touchedTargetRefs` helper + `Config.ImpactPreflight`.
- `fireSchedule` consults it at `windowStart` **after** the existing
  `TouchesMgmtPath` exclusion (which returns early), aborting on veto with a
  **distinct** audit reason (`failure_impact_quorum_risk` /
  `failure_impact_mgmt_path_loss`). A pre-flight error fails closed.

### API (`internal/api/failsim.go`) + wiring (`cmd/vnproxd/failsimwire.go`)
- `GET /failsim/spof-score` and `POST /changesets/{id}/preflight-impact`
  (netRead). The cmd adapter reuses `cephProviderAdapter`'s already-read
  corosync/Ceph side-tables plus the live graph, and is the concrete
  `ImpactPreflighter`.

### Docs
- `docs/api.md` gains a "Failure-impact simulation (T-1604)" section.
- `docs/data-model.md` gains §12 documenting `Impact`/`SPOFEntry` as computed,
  never persisted.

## Safety analysis (required; cross-referenced by test name)

- **False-negative bias by construction.** Where a dimension cannot be
  assessed it is reported in `Impact.NotEvaluated`, never a confident "no
  impact". Codes and their evaluated-preconditions live in `honesty.go`
  (`honestyInventory`), exported by `HonestyInventory()`.
  - `TestSimulate_NotEvaluated` (ceph/tunnels/quorum absent → not evaluated).
  - `TestSimulate_QuorumNotEvaluated_UnresolvableRing` (a voting node whose ring
    address resolves to no interface → quorum not evaluated, never a false
    `quorumRisk:false`).
  - `TestHonestyInventory` (every dimension code is in the audit inventory).
- **Quorum from ring topology, not by name.** `quorumRisk` reuses
  `DetectProtectedRoles`' corosync-role carriers and counts reachable voters
  post-failure. `TestSimulate_QuorumRisk_SharedSwitch` /
  `TestSimulate_QuorumSafe_NodeRemoval`.
- **mgmt-path via the shared resolver, not a second implementation.**
  `mgmtPathLoss` calls `topology.ResolveMgmtPaths` on the post-failure snapshot.
  `TestSimulate_MgmtPathLoss`.
- **T-1103 hook additive, not an override.** The scheduler runs
  `TouchesMgmtPath` first and unconditionally; the impact veto is consulted only
  afterward. `TestSchedule_FailureImpactVeto_Aborts` (veto blocks, audited
  distinctly) and `TestSchedule_MgmtExclusionWinsOverCleanImpact` (a clean
  impact verdict never bypasses the mgmt exclusion; the pre-flight is not even
  consulted when the mgmt gate fires first).

## Soundness boundaries of the model (be explicit)

The model is honest-or-loud, never silently-safe, but its blast-radius
computation has deliberate, documented boundaries:

1. **Connectivity is bridge-level, not per-VLAN-trunk.** A guest is "connected"
   if its bridge retains any live uplink NIC; the simulator does **not** model
   per-NIC 802.1q trunk filtering. This can *under*-report a guest cut off
   because its specific VLAN's trunk NIC died while the bridge keeps another
   uplink. This is a real false-negative risk on the guest dimension — mitigated
   in practice because a bond/bridge/node/uplink removal (the SPOF cases that
   matter) takes the whole bridge uplink, not a single trunk. **Needs hardware
   validation** before this dimension is trusted for per-VLAN isolation claims.
2. **SDN overlay resolution is via `SdnZone.Bridge`.** A vnet whose zone
   declares no underlay bridge is not mapped to an uplink (documented in
   `honesty.go`; such guests surface via `DimGuestConnectivity` when their NIC
   attachment is otherwise unresolvable). EVPN/VXLAN underlay topologies that do
   not populate `SdnZone.Bridge` are a **needs-hardware-validation** gap.
3. **Tunnels are enumerated but their carried-traffic blast radius is minimal.**
   Absent a supplied tunnel model the `tunnels` dimension is `NotEvaluated`
   (honest). The cmd adapter does not yet thread the WireGuard tunnel list in
   (so production currently reports `tunnels` not-evaluated) — a "where present"
   follow-up, not a soundness hole.
4. **Quorum reachability proxy.** A node is "quorum-reachable" if it still exists
   and ≥1 corosync-role carrier retains a live physical uplink. This is a local
   link-state proxy for ring reachability, not a full corosync partition
   simulation; if any voting node's ring is unresolvable the whole dimension
   degrades to `NotEvaluated` rather than guessing. **Needs hardware validation**
   against real corosync partition behavior.
5. **Fail-closed pre-flight.** A pre-flight error blocks the unattended apply.
   This trades availability for safety on the unattended path (by design).

## Grep-able honesty inventory (feature → evaluated | not-evaluated)

| Dimension | Evaluated when |
|---|---|
| disconnected-guests | always (post-failure connected components) |
| stranded-vlans | always (SDN vnet underlay uplink loss) |
| mgmt-path-loss | always (shared `ResolveMgmtPaths`, post-failure) |
| quorum | corosync supplied AND every voting node's ring resolves |
| ceph | Ceph status supplied AND ≥1 network declared |
| tunnels | ≥1 WireGuard tunnel supplied |
| guest-connectivity | every guest NIC attachment resolves |

## Deviations from the card

- **No migration / no kv_test.go bump.** As the card anticipated, this is a pure
  compute core; `Impact`/`SPOFEntry` are never persisted. Migrations remain
  through `0024_oidc.sql`.
- **Switch model.** The card says "switch (T-1205's switch model where present)".
  Rather than depend on T-1205's app-owned switch config, switches are derived
  from LLDP chassis data (a switch every uplink faces is a real SPOF the moment
  LLDP names it), which needs no additional wiring and works on any fixture.
- **`internal/sim` reuse.** The card's deliverable text is "removing target …
  and recomputing connected components". I reuse the *topology* resolver
  (`ResolvePhysicalPath` / `ResolveMgmtPaths`) — `internal/sim`'s own physical
  substrate — for connectivity and mgmt-path, rather than the A→B path-simulator
  entry point (which answers a different question and would require a mutated
  snapshot it isn't structured to take). The post-failure snapshot is rebuilt so
  the *same* resolvers run against it, satisfying AC3's "verified against the
  same `ResolveMgmtPaths` output post-failure".
