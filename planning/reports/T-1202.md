# T-1202 · Global topology, search & palette — completion report

## What was built

### Backend (`internal/federation`, `internal/api`)
Built on T-1201's `federation.Aggregator` (which already fans reads across attached
clusters with per-cluster failure isolation). Extended the aggregator's `PVEReader`
seam with `ClusterResources` and added three read/aggregate operations
(`internal/federation/global.go`):

- **`Aggregator.TopologySummary(ctx)`** — a cheap two-call (`/cluster/status` +
  `/cluster/resources`) fan-out returning one `ClusterSummary` per attached cluster
  (`clusterId`, `clusterName`, `reachable`, node/guest counts, `findings`, `drift`).
  Unreachable clusters are still returned tagged `reachable:false` (so the capsule
  renders greyed rather than being dropped), with the standard
  `partial`/`failedClusters` envelope. `findings`/`drift` are the summary altitude's
  honest, PVE-observable signal (offline member nodes); deeper analysis lives behind
  drill-down — see Deviations.
- **`Aggregator.Search(ctx, q, limit)`** — fans a substring query (node/guest
  names, VMIDs) out to every cluster, returning cluster-namespaced `SearchHit`s
  (each carrying `clusterId`/`clusterName`), stable-sorted by (cluster, label),
  capped at 50. Blank query short-circuits with no fan-out.
- **`Aggregator.ClusterTopology(ctx, id)`** — the lazy drill-down: builds one
  attached cluster's full topology projection purely from its PVE API
  (`/cluster/status` + per-node `/nodes/{n}/network` + `/cluster/resources` + SDN
  tree) via the existing `inventory.From*` ingest functions and `topology.Project`,
  returning the same `topology.Topology` shape `GET /topology` serves. Host-only
  signals (LLDP, netlink) are simply absent from a remote projection, exactly as a
  cluster with no LLDP data renders locally.

Routes (`internal/api/federationtopo.go`, netRead-gated, no CSRF, mounted only when
`FederationAgg` is wired — inert on a single-cluster deployment):
- `GET /federation/topology`
- `GET /federation/topology/clusters/{id}` (404 unknown id, 502 unreachable)
- `GET /federation/search?q=`

Wired `FederationAgg` into `api.Options`, `router.go`'s mount list, and
`cmd/vnproxd/server.go` (the `federationAgg` value already constructed for T-1201).

### Frontend (`web/`)
- **API + queries**: `src/api/federation.ts` (fetchers + types, 404 normalized to
  empty so single-cluster never errors), `src/topology/federation/federationQueries.ts`
  (`useFederationTopologyQuery`, `useFederationClusterTopologyQuery`,
  `useFederationSearchQuery`, `federationIsActive`).
- **Capsule view**: `ClusterCapsule.tsx` (per-cluster capsule — name, findings
  count, drift/unreachable indicators, greyed when unreachable) and
  `GlobalTopologyView.tsx` (the capsule grid).
- **The gate**: `GlobalTopologyGate.tsx` replaces `<TopologyPage/>` on the
  `/topology` route. With **<2 clusters** attached (or federation unwired) it renders
  `<TopologyPage/>` with **zero wrapper DOM** — byte-identical to the pre-Phase-12
  page (AC2). With **≥2** clusters it shows the capsule grid; clicking a capsule sets
  `?cluster=<id>`, which the gate reads (to show a back-to-global affordance) and
  `TopologyPage` reads (to fetch that cluster's projection).
- **Drill-down data source**: `useTopologyQuery(clusterId?)` gained an optional
  `clusterId`; when set it fetches `/federation/topology/clusters/{id}` under a
  cluster-scoped query key. Omitted (the only single-cluster path) it is byte-for-byte
  the original local `GET /topology` behaviour.
- **Command palette (T-903)**: when ≥2 clusters are attached, `CommandPalette.tsx`
  additionally fans `/federation/search` out, groups namespaced hits by cluster, and
  offers a "Switch to <cluster>" action per cluster plus per-hit context switching
  (navigates to `/topology?cluster=<id>` and selects the entity). With <2 clusters
  the federation section never appears — the palette is unchanged.

## Deviations / notes for the next agent
1. **`findings`/`drift` in the summary are PVE-observable only** (offline member
   nodes), not the full cross-node drift/findings engine — that engine operates on a
   locally-built inventory, and building each remote cluster's full inventory on every
   cheap capsule refresh would defeat the "capsule is never the slow part" goal. Full
   per-cluster findings/drift are available on drill-down. This is a deliberate
   altitude split, documented in `global.go` and `docs/api.md`.
2. **Remote drill-down projection is PVE-API-only**: bridges/bonds/VLANs come from
   `GET /nodes/{n}/network`, guests + SDN from the cluster API; LLDP/netlink host
   signals are absent (they belong to that cluster's own on-node vnproxd, unreachable
   over a federated PVE credential). The projection is a genuine, renderable topology
   — sufficient for the drill-down canvas and all its baseline behaviours — but is not
   identical to what that cluster's own vnproxd would render locally. **Needs hardware
   validation** against a real second cluster.
3. **Playwright `federation.spec.ts` was written but not executed** — the e2e harness
   is explicitly out of `make check` (needs downloaded Chromium + free ports + Go
   toolchain per `playwright.config.ts`), and no live/second cluster is available here.
   The spec reuses the two pvemock instances the config already starts, so it needs no
   config change; it should be run on the dev host with `npm run e2e`.
4. **No new migration** — this card is pure read/aggregate over T-1201's existing
   `clusters` table (as the card anticipated).
