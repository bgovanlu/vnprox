# T-1207 · OIDC SSO — completion report

## What I built

OIDC login alongside the existing PVE ticket bridge, with a strict authn/authz split: **OIDC
authenticates the human to vnprox; PVE authorization still gates every cluster-scoped action per
cluster**, and OIDC-derived capabilities are never additive beyond the linked PVE identity's real
ACLs. Backend only (no frontend change); standard library only (no new dependency).

### New code (`internal/auth`)
- **`oidc.go`** — `OIDCProvider`: OpenID Connect discovery, PKCE (S256) authorization-URL
  construction, authorization-code exchange, refresh-token exchange, and RS256 ID-token
  verification against the IdP's published JWKS (issuer/audience/expiry/nonce checked; `alg:none`
  and HS* rejected to close alg-confusion downgrades). Configurable groups claim; string-or-array
  audience/groups decode.
- **`oidc_caps.go`** — the group→role mapping (`MapGroupsToBundle`, union across a user's mapped
  groups) and the authn/authz enforcement point: `IntersectCaps` ANDs the OIDC bundle with the
  linked PVE identity's PVE-derived caps. `capLimiter` seam so both login **and** hourly
  re-derivation apply the OIDC ceiling automatically.
- **`oidc_identity.go`** — `oidcIdentity` adapts an OIDC login to the existing `PVEIdentity`
  interface so OIDC sessions reuse the whole session/cookie/expiry/renewal machinery unchanged;
  `PVELinkResolver` interface. With no PVE linkage, `Permissions` returns an empty set → derived
  caps all-false → intersection strips everything (the split).
- **`oidc_link.go`** — `StorePVELinkResolver` reads the encrypted `oidc_pve_links` table, unseals
  the mapped PVE credential, and builds a linked PVE client; `SealLinkCredential` seals with the
  session cipher.
- **`oidc_service.go`** — `OIDCService` (provider + resolver + group mappings + server-side
  PKCE/nonce state keyed by opaque `state`, single-use with TTL sweep).
- **`oidc_handlers.go`** — `GET /auth/oidc/login`, `POST /auth/oidc/callback`, mounted only when
  configured; `handleLogin`'s session-creation tail refactored into a shared `startSession`.
- **`oidcmock/`** — a stdlib-only mock IdP (discovery, JWKS, RS256 tokens, code+PKCE and
  refresh grants) for tests.

### Store / config / wiring
- **Migration `0024_oidc.sql`** + `store.OIDCPVELinkRepo` (`oidclinks.go`): the app-owned
  OIDC-group→PVE-identity linkage, `credential_enc` sealed with the identical AES-256-GCM
  `SessionCipher`. Bumped the `kv_test.go` schema-version assertion **22 → 24** per the task's
  migration-numbering constraint (0023 left untouched for the concurrent task).
- **`[oidc]` config section** (`internal/config`): `issuer`, `client_id`, `client_secret_file`,
  `redirect_url`, `scopes`, `groups_claim`, `cluster_id`, and `[[oidc.group]]` name/caps mapping
  entries; `Enabled` derived from a set issuer; cap-name validation at load.
- **`cmd/vnproxd/auth.go`**: `setupOIDC` loads the client secret from `client_secret_file`,
  translates group mappings, wires the store-backed resolver, and passes the service into
  `auth.Config.OIDC` (nil when `[oidc]` absent — PVE-only login unchanged).

## What I tested and how
- **Unit** (`oidc_caps_test.go`): `MapGroupsToBundle` union semantics; `IntersectCaps` proving
  AC2 (no linkage → zero caps) and AC3 (capped at PVE ACLs), including symmetry.
- **Provider** (`oidc_test.go`, against the mock IdP): full discovery→AuthCodeURL→Exchange→Verify
  round-trip with groups; refresh-token exchange + rotation (AC4); and rejection of nonce
  mismatch, wrong audience, tampered signature, expired token, and bad PKCE verifier.
- **Integration** (`oidc_integration_test.go`, real HTTP through mounted routes + pvemock for the
  linked PVE identity):
  - **AC1 + AC3** — OIDC login sets a `vnprox_session` cookie with HttpOnly/Secure/SameSite=Strict;
    a full-write group bundle is capped to the linked auditor's read-only PVE ACLs; `/auth/me`
    returns the same capped caps.
  - **AC2** — a full-write group with **no** store linkage is authenticated but holds zero
    cluster-scoped capability.
  - **AC4** — an OIDC session honors the idle-timeout contract (200 within window, 401 past it),
    driven with a controlled clock.
- **Store** (`oidclinks_test.go`): upsert/replace/get/list/delete, unique-per-(cluster,group),
  cross-cluster isolation, sealed-bytes round-trip.
- **Full `make check` is green**: `golangci-lint run ./...` → 0 issues (fieldalignment applied via
  the fieldalignment fixer; no `err` shadowing); `go test ./...` all pass; Vitest 1306/1306;

## Deviations / decisions (flagged per the task card)
- **Per-cluster PVE linkage — resolved via a new encrypted store table, not "papered over."** The
  task said this split may be flagged if it can't be resolved without new PVE capability. It
  resolves cleanly: the mapped PVE credential is stored encrypted in `oidc_pve_links`, and PVE caps
  are re-derived live from it (same path the ticket bridge uses), then intersected. No new PVE-side
  capability was invented. The "first-use PVE-credential prompt" alternative from the card is
  represented by the no-linkage path (authenticated, zero cluster-scoped capability) — the
  interactive prompt UI itself is frontend and out of this backend task's scope.
- **Multi-cluster linkage.** `StorePVELinkResolver` builds linked clients only for the
  local/default cluster; a linkage on a *non-default* federation cluster needs that cluster's
  endpoint from T-1201's `federation.Service.ClientFor` and currently returns "no linkage." This is
  a deliberate scope boundary (keeps auth from depending on federation's client factory) and is
  logged in needs-hardware-validation as a follow-up.
- **Ticket-mode linkage in tests.** Production linkages should use a PVE **API token** (token-mode,
  non-expiring, no login). Tests use ticket-mode because `internal/pvemock` has no API-token auth
  (the same documented dev-ticket deviation the collectors use). The resolver logs a ticket-mode
  linked client in before deriving caps; token-mode needs no login. Consequence: a ticket-mode
  linked identity's ticket can expire over a long OIDC session (hourly re-derivation then keeps the
  previous caps, per the existing `renewal.go` behavior) — a non-issue for production token-mode.
- **OIDC session renewal.** `oidcIdentity.Renew` refreshes the OIDC token at ~half-life (rotating +
  re-verifying), returning the unchanged CSRF and an empty PVE ticket; it does **not** delegate to
  the linked identity's `Renew` (a token-mode client has nothing to renew, and delegating a
  ticket-mode `Renew` error would wrongly invalidate the whole session). Provider-level
  refresh/verify is unit-tested; the renewal loop that drives it is the existing, already-tested
  T-105 machinery.
