# T-1107 — Blueprint sharing bundles

## What was built

Signed, cross-installation blueprint bundles on top of blueprints v2, with a
trust model that never imports an unsigned or untrusted-signed bundle without
an explicit human trust step.

### Backend (`internal/blueprint`)
- `bundle.go` — the `Bundle` envelope `{bundleVersion: 1, blueprint, signature?}`,
  `BundleSignature` (`{alg, publicKeyFingerprint, publicKey, sig}`), `SignBundle`,
  `VerifyBundle`, `Fingerprint`. Signatures are Ed25519 (stdlib `crypto/ed25519`,
  **no new dependency**) over `encoding/json`'s canonical marshaling of the
  `blueprint` field alone — deterministic (fixed struct order + Go's sorted map
  keys), so tampering after signing invalidates it. `publicKey` is carried in the
  envelope (additive beyond the card's literal `{alg, publicKeyFingerprint, sig}`
  listing — flagged in-code): the fingerprint is a one-way digest, not key
  material, so an unknown signer's signature would otherwise be unverifiable.
- `signingkey.go` — `GenerateSigningKeyFile`/`LoadSigningKeyFile` for
  `/etc/vnprox/keys/blueprint-signing.key` (base64 seed, root:root 0600,
  generate-if-absent-never-overwrite — same convention as the session key).
- `trust.go` — `TrustStore` over `/etc/vnprox/keys/trusted-signers/` (one
  `<fingerprint>.json` per pinned signer). Fingerprint is validated as hex
  (path-traversal-safe) before any filesystem access.

### API (`internal/api/blueprint_bundle.go`, wired in `router.go`)
- `GET /blueprints/{id}/bundle?sign=` — optionally-signed bundle export.
- `GET /blueprints/signing-key` — this install's own public key.
- `POST /blueprints/import` — verify + trust-gate + save. Four distinct statuses:
  `imported` / `unsigned` / `untrustedSignature` / `invalidSignature`. Unsigned
  imports only with `{trustUnsigned:true}`; untrusted-signer imports only with
  `{trustNewKey:true}` (which also pins the key). Every attempt (both trust paths
  and every rejection) audited `blueprint.import` with the trust decision +
  signer fingerprint recorded.
- `GET/POST/DELETE /blueprint-signers` — trust-store CRUD, netWrite+CSRF,
  audited `blueprint.signer.add`/`blueprint.signer.delete`.

### Wiring
- `internal/config` — new `[blueprint]` section (`signing_key_file`,
  `trusted_signers_dir`) with `/etc/vnprox/keys/...` defaults.
- `cmd/vnproxd/blueprintbundle.go` — signing key generated at first daemon
  start; `server.go` constructs the trust store and passes both + `auditRepo`
  into `api.Options`.
- `testdata/dev.toml` gained a `[blueprint]` section with `var/`-relative dev
  paths; `cmd/vnproxd/devconfig_test.go`'s `rewriteDevConfig` rewrites them.

### Frontend
- `web/src/api/types.ts`, `web/src/api/blueprints.ts` — bundle/signer types +
  the six new API calls.
- `web/src/blueprints/BlueprintImportDialog.tsx` — three-state import dialog
  (verified/trusted imports with no prompt; unsigned and untrusted each require
  the explicit "I trust…" checkbox before the "Import anyway" action enables;
  invalidSignature offers no import action). `BlueprintsPage.tsx`'s file import
  now routes every file (including a legacy plain-Blueprint export, normalized to
  an unsigned bundle) through this dialog — one import path, gated.

## Migration
**No migration needed.** The signing key and trust store are purely
filesystem-based (`/etc/vnprox/keys/...`), per the card's paths — no SQLite
table. Migration numbers 0010–0012 (reserved for T-1103/1104/1102) and 0013+
are untouched.

## Acceptance criteria
1. Signed export verifies against its own public key — PASS
2. Already-trusted signer imports immediately, audited `trusted:true` — PASS
3. Unknown signer rejected without `trustNewKey`; succeeds with it or after
   separate `POST /blueprint-signers`; both audited — PASS
4. Unsigned rejected by default; succeeds with `trustUnsigned`; audited
   distinctly — PASS
5. Tampering after signing → `invalidSignature`, distinct from `unsigned` — PASS
6. Frontend covers all three states + trust step gates import — PASS
7. Docs updated (`docs/features/blueprints.md` §5, `docs/api.md`); `make check`
   green — PASS
