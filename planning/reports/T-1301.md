# T-1301 — Distributed packet capture engine & permission model

## What I built

A complete server-side packet-capture orchestration engine — the whole trust boundary every
capture consumer (T-1302 UX, T-1307 diagnosis, a future MCP surface) inherits — with a dedicated
permission gate, server-enforced un-overridable caps, bounded/auto-purged capture files, and
audited start/stop.

**New `internal/capture` package (the engine):**
- `Coordinator` orchestrates capture sessions: validates the BPF filter and resolves every target
  *before* invoking any capture process, clamps caps to the configured ceilings, starts one
  session per node (local via `Agent`, remote via `RemoteCapturer`), persists app-owned intent to
  `capture_sessions`, audits `capture.start`/`capture.stop`, reconciles live accounting, and runs
  the retention sweep.
- `Caps`/`clampCaps` — the un-overridable server ceiling logic (a request may ask for a *lower*
  cap, never higher; `retention_hours` is server-only). Every capturing node re-clamps
  independently (`StartLocalSpec`), so no layer trusts another's arithmetic.
- `bpf.go` — a conservative, stdlib-only pcap-filter validator (rejects shell-unsafe characters,
  over-length/over-instruction-ceiling filters, and unknown tokens) run before any capture process.
- `RefResolver` — maps a bridge/bond/VLAN target Ref to its capture interface; guest-NIC/SDN-vnet
  refs are conservatively `ErrUnresolvableTarget` (flagged as needs-hardware).
- `Sweep`/`RunSweepLoop` — the owned auto-purge goroutine: deletes each local session's `.pcap`
  past its `retention_hours` (age reference = `StartedAt`, so a file orphaned by a daemon restart
  mid-capture is still purged once its age cap passes), on the tick-cadence pattern
  `internal/metrics` uses. `StopAll` is the shutdown hook.

**`internal/capturemock` (the fixture agent):** a scripted `capture.Agent` that writes a real
classic-pcap file honoring the packet/byte caps, plus a byte-deterministic corpus generator
(`GenerateCorpus`) covering Ethernet/VLAN/ARP/IP/ICMP/TCP/UDP/DNS/DHCP — the corpus T-1302's
decoder consumes.

**Store:** migration `0011_capture_sessions.sql` + `store.CaptureRepo` (`store.CaptureSession`,
app-owned intent + accounting only).

**Peer API:** additive HMAC-gated `POST /api/peer/capture/start`, `POST /api/peer/capture/stop`,
`GET /api/peer/capture/status` (protocol-version-2-compatible, no bump) with wire types, server
handlers, and client methods.

**HTTP API:** `POST /captures`, `POST /captures/{id}/stop`, `GET /captures/{id}`, `GET /captures`
— gated on **both** `netRead` and the new `capture` capability (mutating routes also CSRF).

**Auth:** `internal/auth/caps.go` gains `CapCapture`/`Capabilities.Capture`, derived from
`Sys.Modify` **AND** `Sys.Console` (strictly stronger than `netWrite`'s `Sys.Modify` alone — a
`netWrite` holder never gets capture).

**Config:** `[capture]` section (`root`, `max_duration_sec`, `max_bytes`, `max_packets`,
`retention_hours`, `max_filter_instructions`).

**Wiring:** `cmd/vnproxd/capture.go` builds the coordinator (`setupCapture`) with all adapters
(store/audit/remote/peer), wires it into `api.Options.Captures`, `peer.ServerOptions.Capture`, the
run group (retention sweep) and a shutdown `StopAll`.

**Docs:** `docs/api.md` (new Captures section + `capture.*` audit vocabulary + peer routes),
`docs/security.md` (Authorization `capture` gate + Host footprint capture-file note),
`docs/data-model.md` (`capture_sessions` table).

1. **AC1 (capability gate):** `internal/auth/caps_test.go` — `captureNeverFromNetWriteAlone` /
   `captureRequiresSysModifyAndSysConsole` / `captureRequiresBoth` table cases prove a
   `netRead`/`netWrite` holder never derives `capture`; and `internal/api/captures_test.go`
   `TestCaptureRoutes_CapabilityGate` proves the route is `403` without `capture`, `201` with it.
2. **AC2 (server-clamped caps):** `capture.TestCapsClampedToConfigServerSide` /
   `TestCapsHonorLowerRequestButNeverHigher` assert effective caps never exceed config regardless
   of the request.
3. **AC3 (filter rejected before any capture process):**
   `capture.TestUnsafeFilterRejectedBeforeAnyCaptureProcess` /
   `TestOversizedFilterRejectedBeforeAnyCaptureProcess` /
   `TestUnresolvableTargetRejectedBeforeAnyCaptureProcess` each assert **zero** agent-Start calls
   via a counting agent. Plus `capture/bpf_test.go`'s full table.
4. **AC4 (multi-point):** `capture.TestMultiPointCorrelatedSessionsAndGroupStop` — two nodes
   produce two `capture_sessions` rows sharing a group id; stopping the group stops both (local
   process + remote peer).
5. **AC5 (auto-purge, injected clock):** `capture.TestSweepPurgesFilePastRetention` and
   `TestSweepPurgesOrphanFileAfterRestartMidCapture` (a fresh coordinator over the same store/root
   with no live process — the restart case).
6. **AC6 (audit start/stop):** `capture.TestAuditOnStartAndStop` (fake auditor) and the golden
   `cmd/vnproxd.TestCapture_AuditRowsGoldenAgainstStore` — exactly one `capture.start`/
   `capture.stop` row each against the real `store.AuditRepo` (the data `GET /audit` serves), with
   actor/target/filter/effective-caps in `detail`.
7. **AC7 (no payload outside the file):** `capture.TestNoPayloadBytesPersistedOutsideCaptureFile`
   asserts the frame payload markers ("vnprox-udp") appear in the `.pcap` file but in **no**
   persisted session row and **no** audit detail. Grep-verifiable corollary: the store/audit code
   paths never receive packet bytes — `store.CaptureSession`/`AuditEvent` carry only counts,
   strings (ref/filter/status/actor), and JSON detail built from those; the only writer of packet
   bytes anywhere is `capturemock`/the future real agent, into `Spec.FilePath`.
8. **AC8:** `docs/api.md`, `docs/security.md`, `docs/data-model.md` updated; peer round-trip +
   HMAC gate tested (`internal/peer/capture_test.go`); store CRUD tested
   (`internal/store/captures_test.go`); config tested (`internal/config/config_test.go`).

## Deviations from the card

- **Capture backend is `internal/capturemock`, not a real AF_PACKET/libpcap agent.** No live
  Proxmox host to capture from, and CLAUDE.md's stdlib-first rule bars a libpcap/eBPF binding.
  Every surrounding safety property (capability gate, un-overridable caps, filter validation,
  audit, retention, peer fan-out) is real and agent-agnostic; the production agent drops in at one
  wiring line (`setupCapture`). Flagged in `planning/reports/needs-hardware-validation.md`.
- **BPF validation is a syntactic gate, not a libpcap compile** (stdlib-only). Same file flags the
  on-hardware `pcap_compile` follow-up.
- **Guest-NIC / SDN-vnet target resolution** returns `ErrUnresolvableTarget` in the default
  resolver (their live device names are runtime-only); a graph-backed resolver is a T-1302/T-1307
  follow-up. Flagged as needs-hardware.
- **Touched one file outside my card: `internal/store/findingevents.go` (T-1007).** Its
  `RunPruneLoop` logged a spurious `context.Canceled` error when a prune was in flight at daemon
  shutdown. This latent bug was benign until this task's added migration (`0011`) shifted SQLite
  timing enough to make `TestFindingEventRepo_RunPruneLoop` hit it deterministically. The one-line
  fix (don't log `context.Canceled`/`DeadlineExceeded` from the prune loop — that is expected
  teardown) is clearly correct and un-breaks the suite my change surfaced; the sibling
  `MetricSampleRepo.RunPruneLoop` has the same latent pattern but its test isn't timing-sensitive,
  so I left it untouched (noted for the next agent).

## Notes for the next agent

- **`make check`'s eslint step fails** with `Cannot find package '@eslint/js'` — `web/node_modules`
  is not installed in a fresh worktree, and this task touches **zero** frontend files (T-1301 is
  backend-only; the capture UX is T-1302). This is the known-flaky `check` job the project MEMORY
  documents.
- **`cmd/vnproxd`'s two full-daemon tests** (`TestRunDaemon_DevConfigServesHealth`,
  `TestRunDaemon_PeerAPIRequiresValidSignature`) are **load-flaky**, not broken by this change:
  they assert `runDaemon` returns within a hardcoded 5s of context cancellation, which under the
  current heavy concurrent multi-worktree machine load occasionally exceeds 5s (I even saw
  `signal: killed`/OOM under full-parallel `go test ./...`). I isolated it rigorously: with the
  sweep actor removed the tests failed **6/6** under load; with it present they passed **6/6** in
  another window — the correlation inverts run-to-run, i.e. it tracks ambient load, not my code. I
  also debug-traced `RunSweepLoop` and confirmed it primes, enters its select, and returns
  promptly on `ctx.Done()` (it is a proper owned goroutine with a shutdown path). They pass
  cleanly when the machine is quiet.
- **The `capture` capability derives from `Sys.Modify` + `Sys.Console`.** If a future card wants a
  different PVE-privilege pairing, `internal/auth/caps.go`'s `DeriveCapabilities` is the single
  source of truth (and `docs/security.md`'s Authorization section documents the choice).
- **`capture_sessions` rows are node-local, self-purging.** For a remote capture the coordinator
  keeps a group-bookkeeping row (it doesn't own/purge the remote file) while the capturing peer
  keeps its own file-ownership row + sweep — see the peer route doc comments.
- The pcap corpus lives in `testdata/captures/` and is regenerated with
  `go run ./internal/capturemock/gen_corpus.go` (byte-deterministic).
