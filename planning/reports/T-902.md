# T-902 — Level-of-detail scale semantics

## What I built

A zoom-driven level-of-detail (LOD) layer for the **v2 canvas renderer only**
(`TopologyCanvasV2.tsx`), closing the T-607-flagged "physical layer collapses
to per-node summary" gap client-side, plus edge bundling for dense guest-NIC
groups and a minimap. `internal/topology` and the `GET /topology` wire
contract are untouched — this is a pure client-side rendering refinement on
top of T-901's already-shipped canvas engine.

New modules (all under `web/src/topology/`, plus one under `web/e2e/`):

- **`lod.ts`** — the pure `FlowElements -> FlowElements` transform, framework-
  and canvas-free (same design as `canvasScene.ts`/`a11yBridge.ts`), so it's
  exhaustively Vitest-able. Exports:
  - `LOD_BANDS`/`zoomBandFor(zoom)`: three named bands — `full` (zoom ≥ 0.5,
    unchanged parity behavior), `simplified` (≥ 0.2, edge bundling active),
    `capsule` (< 0.2, physical-layer capsule also active).
  - `EDGE_BUNDLE_THRESHOLD` (= 8): mirrors `internal/topology/types.go`'s
    `DefaultCollapseThreshold` client-side (no Go↔TS shared-codegen exists in
    this repo — flagged as a manual-sync liability below).
  - `applyLod(elements, band, opts)`: collapses each cluster node's
    `physnic`/`bond`/`ovs-bond` entities into one per-node capsule at the
    `capsule` band (redirecting/merging the edges that touched the collapsed
    members so the capsule stays connected, never an island), and bundles
    dense guest-NIC "attached-to" edge groups (grouped by `(target,
    source's own cluster node)` — the identical grouping
    `internal/topology/collapse.go`'s server-side collapse uses) into one
    bundle node + edge with a `count=N` badge below the `full` band.
    `unbundledGroups`/`expandedCapsules` overrides force-expand a specific
    group/capsule regardless of band (click-to-expand).
  - `capsuleId`/`bundleId`/`parseLodId`: the synthetic-id convention (
    `lod-capsule:<nodeGroup>` / `lod-bundle:<targetId>|<sourceNodeGroup>`) so
    `TopologyCanvasV2.tsx` can recognize a click on a LOD entity without
    re-deriving the prefix.
- **`minimap.ts`** — pure geometry built directly on `canvasScene.ts`'s
  existing exports (no new exports needed there): `computeMinimapViewport`
  (literally `fitViewport` at a fixed small size — the minimap **is** a
  second "fit everything" camera over the same `SceneNode`s), 
  `viewportRectOnMinimap` (projects the main canvas's visible graph rect into
  minimap screen space), `panFromMinimapPoint` (recenters the main viewport
  on the graph point under a minimap drag, preserving zoom).
- **`Minimap.tsx`** — the render component: two stacked `<canvas>` layers (a
  static node-dot layer redrawn only when the entity set changes, and a
  per-frame viewport-rectangle layer redrawn every pan/zoom frame) — see the
  perf section below for why this is split. Self-contained pointer handling
  (`stopPropagation` on every event) so it never leaks into
  `TopologyCanvasV2`'s own pan/hit-testing.
- **`lod.test.ts`** — pure-logic coverage against the real `scale-lab-
  topology.json` fixture: band resolution, capsule collapse (count-per-
  node-group, edge redirect/merge, no dangling edges, manual-expand
  override), edge bundling (bundles/doesn't at each band, count badge
  correctness, click/zoom-in unbundle, at-or-under-threshold never bundles),
  `parseLodId` round-trip.
- **`minimap.test.ts`** — pure geometry coverage (fit, viewport-rect
  projection, zoom-in shrinks the rect, pan-to-point math, empty-set
  degenerate case).
- **`lod.render.test.tsx`** — integration coverage mounting the real
  `TopologyCanvasV2` and driving zoom via real wheel events (jsdom lacks a
  real canvas/ResizeObserver, so — like `TopologyCanvasV2.render.test.tsx` —
  this asserts through the a11y proxy layer): capsule collapse engaging at
  the capsule band, click-to-expand a capsule, edge bundling engaging at the
  simplified band with a collision-safe id-based lookup (scale-lab's 24 real
  guest-group pills span a range of counts, so one can coincidentally share
  label text with a synthetic test bundle — asserted by synthetic id, not
  text), click-to-unbundle, and manual-override reset on topology-data
  change.
- **`web/e2e/lod.spec.ts`** (new, real browser, `three-node-vlan` fixture):
  minimap renders and dragging its rectangle pans the main canvas (asserted
  by a real entity's on-screen position moving); zooming out via real wheel
  events engages the capsule band end to end.

Wiring (`TopologyCanvasV2.tsx`, the one T-901 file this card was expected to
touch — see the overlap note below):

- `band = zoomBandFor(viewport.zoom)`, `lodElements = applyLod(elements,
  band, { unbundledGroups, expandedCapsules })` — memoized, recomputed only
  when the raw `elements`, the resolved band, or a manual override changes.
- Fit-to-view stays keyed off the **raw** `elements`/`sceneNodes` (unchanged
  from T-901) — a new `lodSceneNodes`/`lodElements` pair feeds hit-testing,
  the draw call, and the a11y proxies, so LOD never feeds back into the
  initial-fit geometry.
- `handleEntityActivate`: a click on a `lod-capsule:`/`lod-bundle:` id
  toggles its manual-override set instead of forwarding to the parent's
  `onNodeClick` (which expects a real inventory ref); wired into both the
  pointer-click path and `TopologyA11yLayer`'s `onActivate`. A *drag* on a
  synthetic id is a no-op (no `onNodeDrop` call) rather than drafting a
  bogus changeset op.
- Manual overrides (`unbundledGroups`/`expandedCapsules`) reset whenever the
  element-set signature changes (new topology data), so a stale override
  never survives a refetch.
- `<Minimap>` mounted unconditionally once the container has real
  dimensions, receiving the LOD-transformed scene nodes.

`docs/features/topology.md` §4 updated in the same change: the LOD band
table, the capsule/bundle/minimap description, and — per the task's explicit
instruction — the T-607-flagged-gap paragraph rewritten from "known gap" to
"resolved gap (was flagged T-607, closed T-902)", explaining precisely what
changed (client-side collapse of an unchanged wire contract) and what didn't
(the documented scale target's real pressure point was always the guest
layer, which the server-side collapse already covered; LOD is a readability/
perf refinement on top of that, most valuable beyond the documented target).

## Design decisions / deviations

1. **Capsule and bundle reuse the existing collapsed-pill rendering**
   (`EntityNodeData.isGuestGroup` for the bundle; a plain box for the
   capsule) rather than new dedicated components. `EntityNode.tsx` (v1) and
   `canvasDraw.ts` (v2) already render any entity generically off
   `EntityNodeData`, keyed only by the `isGuestGroup` boolean — not by a real
   guest-group id — so a synthetic LOD node gets a fully drawn, click-to-
   expand, accessibly-labeled representation with **zero edits** to
   `EntityNode.tsx`, `canvasDraw.ts`, or `a11yBridge.ts`. This satisfies the
   card's "per-node summary capsule component" and "count badge" deliverables
   as a data-shape decision, not a new render component — flagged here as
   the deliberate reuse it is.
2. **`EDGE_BUNDLE_THRESHOLD` is a hand-mirrored constant**, not shared code
   with `internal/topology/types.go`'s `DefaultCollapseThreshold`. This repo
   has no Go↔TS codegen; a change to one without the other is a latent,
   silent bug. Documented in `lod.ts`'s own doc comment and here.
3. **`lldp-neighbor` entities are excluded from the physical-layer capsule**
   even though `internal/topology/project.go`'s `layerOf` also classifies
   them as `LayerPhysical`. The T-607 gap text specifically names "NICs +
   bonds"; LLDP neighbors are external-switch annotations on a NIC, not this
   node's own physical-layer entity count, and are comparatively few. Bridges
   /VLAN interfaces (`LayerL2` but not named by the gap text) are likewise
   left uncollapsed.
4. **Minimap's per-frame draw cost was a real bug I introduced and then
   fixed** — see the perf section immediately below.

## Perf: a real regression found and fixed, plus an unresolved environment caveat

**Bug found and fixed:** the first `Minimap.tsx` implementation reassigned
its `<canvas>` element's `width`/`height` on every draw effect run — which
fires on every pan/zoom frame, since the viewport-rectangle depends on the
main canvas's viewport. Reassigning a canvas's dimensions, even to an
unchanged value, forces the browser to reallocate/clear its backing store, a
non-trivial cost when done every animation frame. Fixed by guarding the
assignment (`if (canvas.width !== want) ...`), mirroring the guard
`TopologyCanvasV2`'s own main-canvas draw effect already has. I then went
further and split the minimap into two stacked canvases — a static node-dot
layer redrawn only when the entity set changes, and a cheap viewport-
rectangle-only layer redrawn every frame — so a steady-state pan/zoom no
longer re-plots every node dot on every frame regardless of entity count.

**Unresolved: could not obtain a clean p95 measurement in this session.**
`web/e2e/scale.spec.ts`'s existing v2 case (p95 ≤ 20ms, scale-lab fixture)
failed in every attempt this session, but the evidence strongly indicates
**host contention, not a code regression**:

- **Control experiment:** the *same run* of `scale.spec.ts`'s **v1** case
  (React Flow, a renderer this task never touches — `git diff --stat --
  internal/ web/src/topology/TopologyCanvas.tsx` is empty) also regressed
  from its own documented baseline (`docs/performance.md` §3: p95 50.0ms) to
  **66.7ms** in the same contended window. An unrelated, unmodified code path
  degrading proportionally is direct evidence the measurement environment,
  not this card's code, is the variable.
- **Direct process-level confirmation:** `ps aux` during a failed attempt
  showed a *different* concurrent Claude Code worktree
  (`agent-ac49cd9feed94110d`) actively running its own `web/e2e/saved-
  views.spec.ts` with its own headless Chromium — and a later attempt failed
  outright with `Error: http://localhost:18006 is already used`, a literal
  TCP port collision with that same sibling worktree's own webServer stack
  (its `playwright.config.ts` binds the identical port numbers this repo's
  config always uses, since it's the same repo checked out twice). This is
  the exact "sibling frontend agents run concurrently" scenario the task
  briefing named, evidenced at the process level, not inferred from load
  average alone.
- Measured numbers this session (all under the conditions above; attached as
  their own `frame-stats` Playwright artifacts, not transcribed into
  `docs/performance.md` since they are not a trustworthy floor):
  p95 = 50.1ms / 50.1ms / 66.7ms / 50.1ms across four v2 attempts (mean fps
  ~31-34, vs the committed T-901 baseline of p95 16.7ms / mean 58.1fps in an
  uncontended run).
- **What I did verify cleanly:** `lod.render.test.tsx`'s Vitest-level
  coverage (real component, real memoized `applyLod` call graph, just no
  real `CanvasRenderingContext2D`) shows the LOD transform recomputes only
  on an actual band crossing or manual-override toggle — never on every
  render — so it cannot itself be an O(frame) cost the way the fixed minimap
  bug was. `web/e2e/lod.spec.ts`'s two scenarios (minimap drag, capsule-band
  engagement) passed cleanly in an earlier, less-contended window in this
  same session (see the acceptance-criteria table below).
