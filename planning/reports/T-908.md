# T-908 · Inspector v2 (pinnable multi-inspector, side-by-side compare, per-pane metrics)

## Summary

Implemented in full, building on the existing single-entity `InspectorPanel.tsx`/`MetricsTab.tsx`
rather than replacing them. `InspectorPanel` gained a pin control; `TopologyPage` now mounts a new
`InspectorStack.tsx` container (owning a pure pane-selection reducer, `inspectorStack.ts`) instead
of a bare `InspectorPanel`. Selecting a new entity while nothing is pinned still replaces the
single inspector exactly as before T-908; once something is pinned, a new selection is additive
(up to `MAX_INSPECTOR_PANES = 4`). Two panes of the same kind render `InspectorCompareView.tsx`'s
aligned compare grid (shared Fields/Metrics tab strip, two columns); a mismatched-kind pair (or
3-4 panes) falls back to plain independent panes with an explanatory banner when mismatched — never
a broken layout.

## Deviations from the task card (with reasons)

1. **A single pinned pane (not just 2+ panes) switches to the non-modal region.** The task card
   frames the layout split as "1 pane → modal, 2+ panes → side-by-side," but a real bug surfaced
   writing the e2e test: the original modal `<Drawer>` (a Radix `Dialog.Root`, full-screen overlay)
   blocks all other interaction by design — including the Search button pinning is supposed to let
   the user reach next. `AppShell.tsx` already documents this exact class of bug in its own doc
   comment (a `fixed inset-y-0` overlay colliding with a page's own top-row controls — the fix
   there was "push content down instead of floating on top"). Fix here, mirroring
   `ChangesetDrawer.tsx`'s established pattern for this app (`fixed bottom-4 right-4` with a bounded
   `max-h-[80vh]`, not `inset-y-0`): (a) `InspectorStack` renders the modal `<Drawer>` only for a
   single **unpinned** pane; the moment that one pane is pinned, it moves to the same non-modal
   region a second pane would use. (b) The region itself is bottom-right-anchored with a bounded
   max-height rather than spanning the full viewport height, so it never overlaps the page's own
   toolbar. Caught and fixed via the actual Playwright run against the real stack, not just Vitest
   — noted since it's a behavior beyond the card's literal 1-vs-2+ pane split, though it's in
   service of the same acceptance criteria (AC1/AC4) and doesn't change what ships for the
   already-covered "2 same-kind panes compare" or "3-4 panes" cases.
2. **`DrawerTitle`/`DrawerDescription` (Radix `Dialog.Title`/`Description`) can't be reused verbatim
   in the embedded (non-modal, no `Dialog.Root`) branch** — they throw `must be used within Dialog`
   outside a `Dialog.Root` context. Embedded mode renders plain `<h2>`/`<p>` with the same visible
   text instead; the region's own `aria-label` supplies the accessible name in that branch (Radix's
   `aria-labelledby` wiring is unavailable without the context).
3. **Compare-mode close-button `aria-label`s include the node** (`Close {label} (${node})`, on both
   `InspectorPanel`'s embedded Close button and `InspectorCompareView`'s `ComparePaneHeader`), not
   just the label. Two same-kind entities being compared very often share the same label (e.g.
   `bond0` on every node in `three-node-vlan`) — an unqualified `aria-label` would make the two
   Close buttons indistinguishable to assistive tech and to the e2e test itself. Minor, additive a11y
   fix in service of AC1/AC4, not called out explicitly by the card.
4. **Playwright webServer startup flakiness**, unrelated to this task's code: this environment runs
   sibling agents concurrently (confirmed via `ps aux` — another worktree's Playwright run,
   `govulncheck`, and a `podman build` were active during testing), which intermittently starved the
   default `playwright.config.ts` webServer group (5 mock-PVE+vnproxd pairs) past its readiness/test
   timeout, or left stale processes holding ports 8006-38007 between attempts. Worked around by
   killing stale listeners between retries and using `--timeout=240000` for local verification runs;
   the spec itself needed no changes once the servers were actually up (confirmed passing at 20.1s
   real runtime). Not a change to `playwright.config.ts` — flagging per CLAUDE.md rather than
   touching shared CI config unilaterally.

## What the next agent should know

- `InspectorStack` is now the single source of truth for which entity refs have an open pane and
  whether each is pinned; `useTopologyStore`'s `selectedId` is unchanged in meaning (still "last
  clicked ref," still drives canvas/switch-view selection highlighting) — `InspectorStack` merely
  *watches* it via a `useEffect` and feeds it through `selectPane`, it doesn't own or replace it.
- The pin/close/compare rules live in `inspectorStack.ts` as plain functions
  (`selectPane`/`closePane`/`togglePin`) with no React dependency — reuse these directly for any
  future feature that needs the same "additive selection while something is pinned, capped, evict
  oldest unpinned first" behavior, rather than re-deriving it.
- `InspectorPanel`'s `embedded` prop is intentionally load-bearing beyond just "no modal wrapper":
  it also swaps `DrawerTitle`/`DrawerDescription` for plain elements and adds the Close button. Any
  future non-modal reuse of `InspectorPanel` should go through this same prop rather than
  hand-rolling another bypass.
- Compare mode is currently scoped to the Fields and Metrics tabs only (not Raw source/Provenance/
  Related/Management path/FDB/LACP) — the task card's own wording ("fields and metrics tabs aligned
  column-wise") only asked for these two. A mismatched-kind or 3+-pane fallback still gets every tab
  via the ordinary embedded `InspectorPanel`, so no capability is lost, just not aligned side by side
  for the two-pane same-kind case.
