# T-1001 · Prometheus exporter — completion report

**`make check`:** green (Go lint/vet/tests, `govulncheck`, web eslint/tsc/vitest, `npm audit`) — see "Verification" below.

## What was built

- **`internal/metrics/sampler.go`** — new `CounterSnapshot` type and `Sampler.AllCounters()` method: returns the most-recently-observed **raw** counters (not rates) for every ref the sampler has ingested at least once, sorted by ref string for a deterministic scrape body. No new collection logic — reads the same `live` map `Ingest`/`Live` already maintain.
- **`internal/store/token.go`** (new) — `GenerateHexTokenFile`/`LoadHexTokenFile`: a generic hex-encoded 256-bit secret file helper (root:root 0600, "never silently overwrite" contract), distinct from `cipher.go`'s `GenerateKeyFile`/`LoadKeyFile` (which write raw 32-byte binary, unsuitable for an HTTP header value) — mirrors `internal/peer`'s cluster-secret on-disk format for the same reason (must be directly usable as `Authorization: Bearer <token>` text and pasteable into a Prometheus `bearer_token_file`).
- **`internal/api/metrics_exporter.go`** (new) — `GET /metrics`: renders the eight `vnprox_iface_*` counter families (via `MetricsCounterService`/`Sampler.AllCounters`), `vnprox_findings_open{severity}` (via the existing `FindingsService` seam), `vnprox_drift_open` (via the existing `DriftService` seam), `vnprox_changesets{status}` (via the existing `ChangesetService.List` seam), and `vnprox_build_info{version}`, as Prometheus text exposition (`text/plain; version=0.0.4`). Auth is its own middleware (`metricsExporterAuth`): CIDR allowlist check first (403), then `crypto/subtle.ConstantTimeCompare` bearer-token check (401) — mounted directly in `NewRouter`, outside `AuthService.SessionMiddleware`/CSRF entirely (the one documented exception). Every dependency is nil-safe; the route itself doesn't mount at all when the token is empty.
- **`internal/config/config.go`** — new `[metrics]` section: `MetricsConfig{Enabled, KeyFile, AllowFrom []*net.IPNet}`. `Enabled` defaults to `true` (uses a `*bool` in the raw TOML struct to distinguish "absent" from "explicit false"); `AllowFrom` CIDR strings are parsed and validated at `Load` time (fails fast on a bad entry, matching every other section's convention).
- **`internal/api/config.go`** — `InstanceInfo` gains `MetricsEnabled bool` (`json:"metricsEnabled"`), no secret exposed.
- **`internal/api/router.go`** — `Options` gains `MetricsCounters MetricsCounterService` and `MetricsExporter MetricsExporterConfig`; `mountMetricsExporterRoutes` wired into `NewRouter`.
- **`cmd/vnproxd/metricsexporter.go`** (new) — `setupMetricsExporterToken`: load-or-generate the token file at daemon start (same "generate if absent" convention `setupAuth`'s session key uses), returning `nil` when `[metrics] enabled = false` so the daemon never even touches the key file.
- **`cmd/vnproxd/server.go`** — wires the token, `metricsSampler` (as `MetricsCounters`), and `api.MetricsExporterConfig{Token, AllowFrom, BuildVersion}` into `api.NewRouter`; `Instance.MetricsEnabled` set from `cfg.Metrics.Enabled`.
- **Docs**: `docs/api.md` (Auth section's one-line exception note + new "Metrics exporter (T-1001)" subsection with the full metric table and auth story), `docs/security.md` (new Authentication subsection "Metrics scrape token (T-1001, addition)" + a Transport addition + a threat-model row), `docs/features/monitoring.md` §4 (corrected from "gated to `Sys.Audit`" to the real scrape-token story, flagged as a correction), `docs/deployment.md` (`[metrics]` added to the example config).
- **Dev config fixtures**: `testdata/dev.toml` + `dev-scale.toml`/`dev-sim.toml`/`dev-mgmt.toml` all gained `[metrics] key_file = "var/..."` overrides (production default is `/etc/vnprox/keys/metrics.key`, which needs root) — `cmd/vnproxd/devconfig_test.go`'s `rewriteDevConfig` updated to rewrite it for the test harness. **Found and fixed a real bug this way**: before this fix, three existing `cmd/vnproxd` integration tests (`TestRunDaemon_DevConfigServesHealth`, `TestRunDaemon_PeerAPIRequiresValidSignature`, `TestSecretsNeverAppearInLogs`) failed with `mkdir /etc/vnprox: permission denied` once `[metrics].Enabled` defaulted to `true`, because `runDaemon` now unconditionally tries to generate the token file.

## Deviations / decisions

- **New dependency**: `github.com/prometheus/common` (pulls in `client_model`, `goautoneg`, `protobuf`) added to `go.mod`, used **only** in `internal/api/metrics_exporter_test.go` (`expfmt.TextParser`) to validate the exposition text is well-formed — never imported by `vnproxd`'s own code, per the task card's explicit allowance ("not a runtime dependency"). This also bumped `golang.org/x/sys` 0.44.0 → 0.46.0 (transitive minimum-version requirement); `go build ./...` and the full test suite (including `internal/host`'s netlink-backed tests) pass unchanged.
- **`GET /metrics` path**: mounted at `/api/v1/metrics` (inside the existing `/api/v1` subrouter), matching this codebase's convention that every route except `/api/ws` and `/api/peer/*` lives under `/api/v1` — the task card didn't specify an exact path; documented as such in `docs/api.md`.
- **`[metrics] enabled` default**: the card didn't say whether the exporter should default on or off. I defaulted `true` (unlike T-1002's flow listeners, which the phase-10 doc explicitly says default off) because the route is read-only, separately authenticated, and exports no secret — an operator who wants it off sets `enabled = false`. Flagging this in case a sibling task or later review disagrees.
- **`vnprox_changesets` label set**: the card's table lists exactly six statuses (`draft|applying|awaiting_confirm|committed|rolled_back|failed`); `change.StatusValidated` and `change.StatusDiscarded` are deliberately never counted/labeled — not in the documented vocabulary. Noted in both the code comment and `docs/api.md`.
- Reused `DriftService`/`FindingsService`/`ChangesetService` — the router's existing seams for `GET /drift`, `GET /findings`, `GET /changesets` — rather than inventing new interfaces, so no sibling task touching those seams should see a new conflicting interface shape.
