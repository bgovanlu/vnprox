# T-1706 · Embeddable views & Grafana panels — completion report

## What was built

Read-only, token-scoped embeds of the map / home dashboard / posture report,
plus in-repo Grafana panel render components backed by the T-1001 exporter and
the T-1104 WS `"events"` topic. No new mutation path, no new privilege surface,
and **no migration** (see the embed-token design note below).

### Backend (`internal/api`)

- `internal/api/embed.go` (new):
  - `POST /embed/tokens` — mints a read-only embed token. Enforces a
    **read-only ceiling before** the ordinary per-user ceiling: any scope
    outside `{netRead, sdnRead, fwRead, audit}` is rejected `400`
    (`validation_failed`) **regardless of the minting user's own
    capabilities**, then the existing `TokenMinter.ValidateTokenScopes` seam
    applies the `403` per-user ceiling. Reuses T-1104's `api_tokens` store,
    audit (`token.create` with `embed:true` detail), and one-time raw reveal.
  - `GET /embed/{map,dashboard,posture}` — top-level HTML shell routes (outside
    `/api/v1`, like `/api/ws` and `/api/peer`). A dedicated `embedViewAuth`
    middleware authenticates the token from the **`?token=` query parameter
    only** and never the session cookie; missing/unknown/revoked → `401`, a
    token carrying any write scope → `403`. `/embed/posture` serves a documented
    dark state (`200`, HTML with `data-embed-state="posture-unavailable"`) when
    posture (T-1607) isn't wired.
- `internal/api/router.go` — wired `mountEmbedTokenRoute` (under `/api/v1`) and
  `mountEmbedViewRoutes` (top-level, `opts.Posture != nil` decides posture
  availability).
- `internal/api/embed_test.go` (new) + `GetByHash` added to the shared
  `fakeAPITokenStore`: covers AC1 (write-scope rejection, table over 6 write
  scopes), successful mint (`embed:true`, one-time reveal, hash-only storage),
  valid-token shell serving, revoked→401, unknown→401, **cookie-rejected→401
  (AC6)**, write-scoped-token→403, **posture dark state (AC5)**, unknown-view→404.

### Frontend (`web/`)

- `web/src/embed/embedToken.ts` — module-level embed-token state; `api/client.ts`
  now sends `Authorization: Bearer <token>` and `credentials: "omit"` in embed
  mode (never falls back to the cookie).
- `web/src/embed/EmbedFrame.tsx` — reads `?token=`, stashes it, renders a
  chrome-free read-only shell (no AppShell, no RequireAuth, no nav/mutation
  chrome); missing token → explicit state.
- `web/src/embed/EmbedMap.tsx` — read-only topology projection over
  `GET /topology` (grouped by node, status dots + badges); the interactive
  editor's context-menu/inspector/edit chrome is simply **not mounted** (removed
  at the component level, not CSS-hidden).
- `web/src/embed/EmbedDashboard.tsx` — reuses the existing T-904 dashboard tile
  components (all already read-only, netRead-backed).
- `web/src/embed/EmbedPosture.tsx` + `web/src/api/posture.ts` (new) — read-only
  posture score + factor breakdown; a `404` renders the documented "not yet
  available" state.
- `web/src/App.tsx` — `/embed/{map,dashboard,posture}` routes outside
  `RequireAuth`/`AppShell`.
- Tests: `EmbedMap.test.tsx` (AC2 read-only DOM: zero buttons/edit affordances +
  asserts bearer header & `credentials:"omit"`), `EmbedPosture.test.tsx` (AC5
  frontend), `grafana/MetricsPanel.test.tsx` + `grafana/EventAnnotationsPanel.test.tsx`
  (AC4).

## Deviations / interpretation calls

- **No persisted `embed` column (deviation from the literal "additive
  `embed:true` flag" wording).** The card hinted this likely needs no migration,
  and migrations are forward-only. Rather than add column `0032`, an embed token
  is defined **structurally** by its read-only scope set: the mint endpoint
  rejects write scopes, and the embed view auth re-checks read-only-ness on every
  request (a write-scoped token is refused `403`). This satisfies the full stated
  security model and every AC with zero schema change. `embed:true` is returned in
  the mint response as a marker. Consequence: an embed token also functions as an
  ordinary read-only bearer token, and `GET /tokens` does not visually distinguish
  embed tokens — acceptable, since the security ceiling is read-only either way.
  **Migrations and `kv_test.go` were left untouched (schema version stays 27).**
- **`/embed/posture` is now "lit," with the dark state retained.** T-1607 has
  since shipped, so posture is served live when wired; the documented dark-state
  response is retained for the un-wired case (and is what the AC5 test asserts) —
  the honest reading of the card's cross-phase "wired but dark" gate.
- **EmbedMap is a purpose-built read-only projection**, not the full interactive
  `@xyflow` editor with affordances stripped. Reusing the editor and removing
  mutation entry points "at the component level" is achieved by not mounting them
  at all; this is more robustly read-only than CSS-hiding and avoids dragging the
  editing chrome into an embed. EmbedDashboard/EmbedPosture do reuse existing
  components/data.
- **Grafana: in-repo render components + external packaged plugin** (stated
  above), the boundary the card asked to pick.

## Needs live validation (no hardware/live service in this environment)

- The packaged Grafana plugin against a **live Grafana** instance (plugin
  registration, Prometheus datasource wiring, WS event-annotation datasource) —
  only the render components + their data contract are validated in CI here.
- Real `<iframe>` cross-site embedding behavior (CSP `frame-ancestors`, cookie
  `SameSite` interaction) against a browser — the cookie-rejection invariant is
  enforced and unit-tested server-side, but end-to-end iframe embedding on a real
  page is unexercised.
