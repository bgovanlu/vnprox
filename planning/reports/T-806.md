## What was built

**Backend — `POST /simulate/verify` persistence + `GET /simulate/verify/eligibility`**
(`internal/api/simulate.go`, `internal/api/router.go`)

- `GET /simulate/verify/eligibility?ref=`: answers "can Verify live even attempt a probe for this
  src right now" without running the honesty-contract-laden ICMP/TCP probe itself. Resolves `ref` to
  a qemu guest via the existing `resolveQemuGuestNicOwner` (no live call — pure inventory lookup);
  only if that holds, pings the guest agent's *transport* channel via a new
  `internal/pve.Client.AgentPing` (`POST /nodes/{node}/qemu/{vmid}/agent/ping`) — deliberately not
  `GetGuestAgentInterfaces`, since a guest can have a perfectly reachable agent with zero configured
  interfaces (sim-lab's own vm-a has no `agent_interfaces` block, only `agent_exec_outcomes` — using
  the interfaces call as the reachability oracle would have wrongly marked it ineligible). Response
  `{eligible, reason?}`, `reason` one of `not-qemu`\|`agent-unreachable`. No PVE session → `422
  pve_session_required` (T-701's code for the same condition). Mounted only when `ProbeClients` is
  wired, same nil-safety as `/simulate/verify`; not audited (makes no claim about the guest's network
  reachability, only whether an attempt could be made).
- `internal/pve.Client.AgentPing` + `internal/pvemock.handleGuestAgentPing` (new
  `POST /nodes/{node}/qemu/{vmid}/agent/ping` route, gated the same as the other `agent/*` routes) —
  mirrors `AgentExec`'s exact `AgentUnreachable` failure-mode precedent.
- `handleSimulateVerify` now also calls `recordDivergence` after computing `diverges`: on `true`,
  upserts a `store.SimDivergenceFinding` row keyed by a new content-derived tuple id
  (`simDivergenceTupleKey`, `"probe:sim_divergence|<src>|<dstKind>:<dstRefOrIp>|<proto>|<port>"`); on
  `false`, clears any prior row for that same id (a re-verified tuple that no longer diverges stops
  claiming one). Nil-safe (`Options.SimDivergence`); errors from the store write are swallowed
  (best-effort side-record), matching `auditSimulateVerify`'s own tolerance.

## A real bug this task's own e2e run caught and fixed

Running the new e2e scenario twice in one session (divergence test, then a second `/tools` visit)
crashed the whole `/tools` page behind its error boundary. Root cause: `findings.Finding.Nodes
[]string` has **no `omitempty`** — a nil slice marshals to JSON `"nodes":null`, and
`web/src/findings/filters.ts`'s `nodesIn`/`filterFindings` do `for (const n of f.nodes)` /
`f.nodes.includes(...)` unconditionally. My first `probeDivergenceToFinding` draft never set `Nodes`
at all (nil), and `FindingsStreamPanel` (rendered as one of `/tools`'s own tabs) fetches `GET
/findings` on every visit — the very first persisted `sim_divergence` finding crashed the page for
every subsequent navigation. Fixed at the producer: `probeDivergenceToFinding` now always emits a
non-nil `Nodes` (parsed from the src ref's own node via `inventory.ParseRef`), with a Go-level test
asserting the marshaled JSON never contains `"nodes":null`. **Flagged, not fixed**:
`ipamConflictToFinding` (`cmd/vnproxd/findings.go`) has the exact same latent bug — it never sets
`Nodes` either — but no fixture currently produces an active IPAM conflict finding on any page this
task touches, so it's never been exercised. Left alone (out of scope, and touching shared IPAM code
risked colliding with sibling agents' concurrent work), but worth a follow-up ticket.

## Deviations from the task card (with reasons)

- **Worktree was stale at dispatch** (see the flagged note at the top) — resolved via a clean
  fast-forward merge of `main`, not a cherry-pick (unlike T-802's own report, which had to
  cherry-pick a single docs commit; here the full T-801/802/804/805 history was needed and merged
  cleanly).
- **Added `GET /simulate/verify/eligibility`**, not named anywhere in T-806's or T-802's own card
  text. The card requires gating on "a guest-nic src resolved to a qemu guest with a reachable guest
  agent" but neither card specifies *how* the frontend is supposed to know guest-agent reachability
  ahead of a click — no existing inventory/topology field carries it (confirmed by search: `Guest`
  only has `Type`/`Status`/`Name`/`Node`/`VMID`; no agent-reachability signal exists anywhere in
  `internal/inventory`, `internal/ipam`, or the topology badge vocabulary). Reusing
  `GetGuestAgentInterfaces` (the only existing "ask the agent something" call) as the reachability
  oracle would have been wrong, since an agent-reachable guest can legitimately report zero
  interfaces (sim-lab's own vm-a). Added a new, minimal, unaudited, read-only endpoint backed by a
  new `internal/pve.Client.AgentPing` (the real PVE `agent/ping` transport-liveness command) instead
  of guessing or omitting the reachability check. Flagged here since it's new API surface beyond what
  either card's text enumerates, though it's the most direct way to fulfill T-806's own explicit UX
  requirement.
- **Severity for `sim_divergence` is always `warning`**, not derived from which direction the
  divergence runs (a false-allow vs. a false-deny). Neither card specifies a severity rule; `warning`
  was chosen as the honest default (the producer genuinely can't tell from the tuple alone whether a
  specific disagreement is security-relevant) rather than guessing `error` for one direction and
  `warning` for the other.
- **Fixed a real, pre-existing latent bug** (`Finding.Nodes` nil → JSON `null` → frontend crash) at
  my own producer and left the identical bug in `ipamConflictToFinding` unfixed — flagged above,
  not silently patched, to avoid unrelated scope creep into shared IPAM code mid-sprint.
- **Added a "View in simulator" action** to `FindingsStreamPanel.tsx` beyond the card's literal text
  (which only specifies the finding *carries* a deep link) — without it, the deep link the backend
  computes would have had no UI entry point reachable from the unified findings stream page itself.
  Judged in-scope since it's what makes the "deep-link ... back into the simulator" deliverable
  actually deliver something a user can click.
